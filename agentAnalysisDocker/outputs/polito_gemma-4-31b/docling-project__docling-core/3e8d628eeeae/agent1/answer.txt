The commit replaces `yaml.FullLoader` with `yaml.SafeLoader` in two files. 

In `file_01`, the change occurs in a method that reads a file from a `filename` (likely provided as input) and loads it using PyYAML. Using `yaml.FullLoader` (or `yaml.load` without a safe loader) can lead to arbitrary code execution if the YAML input is untrusted, as it allows the instantiation of arbitrary Python objects. Switching to `yaml.SafeLoader` restricts the loading to simple Python objects, effectively mitigating this vulnerability.

In `file_02`, the change is in a test case. While less critical than production code, it follows the same security practice.

The vulnerability addressed is the deserialization of untrusted data, which is a classic security flaw in YAML parsing.
