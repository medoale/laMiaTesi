The analysis of the provided repository revealed a security vulnerability in the `HttpClientUtil.java` class within the `io.dataease.utils` package.

Specifically, the `buildHttpClient(boolean ssl)` method implements a custom SSL context that disables all certificate validation. It uses `builder.loadTrustMaterial(null, (X509Certificate[] x509Certificates, String s) -> true);`, which unconditionally trusts any certificate presented by the server, regardless of its validity, issuer, or expiration. Additionally, it employs `NoopHostnameVerifier.INSTANCE`, which skips the verification that the certificate's hostname matches the server's hostname.

This combination of disabled certificate and hostname verification makes the application susceptible to Man-in-the-Middle (MitM) attacks. An attacker could intercept the encrypted traffic and present a fraudulent certificate, which the application would trust, allowing the attacker to decrypt, read, and potentially modify sensitive data being transmitted between the application and the remote server.
