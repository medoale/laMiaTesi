The commit modifies the `propertiesAction` method in `SettingsController`.

In the `before.txt` version, the permission check `$this->checkPermission('predefined_properties');` is performed inside the `if ($request->get('data'))` block. This means that if a request is made to the `/properties` route without a `data` parameter, the code bypasses the permission check and proceeds to the `else` block (lines 314-344), which fetches and returns a list of predefined properties.

In the `after.txt` version, the permission check `$this->checkPermission('predefined_properties');` is moved to the very beginning of the `propertiesAction` method (line 264), ensuring that any request to this endpoint—regardless of whether it's for listing properties or performing an action on them—is subject to the permission check.

This fixes a Broken Access Control vulnerability where an unauthorized user could list predefined properties by simply omitting the `data` parameter in the request.
