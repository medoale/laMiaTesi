The commit introduces security limits to the `PdfWriter` class in the `pypdf` library, specifically when operating in `incremental` mode.

In the `before` version of `clone_reader_document_root`, the code was:
```python
if self.incremental:
    self._objects = [None] * (cast(int, reader.trailer["/Size"]) - 1)
    for i in range(len(self._objects)):
        o = reader.get_object(i + 1)
        if o is not None:
            self._objects[i] = o.replicate(self)
```
This code relied on the `/Size` entry in the PDF trailer to allocate a list (`self._objects`). A maliciously crafted PDF could specify an extremely large `/Size` value, leading to an `OutOfMemoryError` (Denial of Service) as Python attempts to allocate a massive list.

The `after` version introduces `incremental_clone_object_count_limit` (default 500,000) and `incremental_clone_object_id_limit` (default 1,000,000). The new `_collect_incremental_clone_object_ids` method validates the actual number of objects and the maximum object ID found in the PDF's cross-reference (xref) table before allocation. If these limits are exceeded, a `LimitReachedError` is raised.

This change directly addresses a resource exhaustion vulnerability, which is a form of Denial of Service (DoS).
