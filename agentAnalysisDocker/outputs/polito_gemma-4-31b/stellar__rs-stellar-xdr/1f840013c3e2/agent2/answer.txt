The commit modifies the `from_str` implementation for the `StringM<MAX>` type.

In the version before the commit:
```rust
impl<const MAX: u32> core::str::FromStr for StringM<MAX> {
    type Err = Error;
    fn from_str(s: &str) -> core::result::Result<Self, Self::Err> {
        let b = escape_bytes::unescape(s.as_bytes()).map_err(|_| Error::Invalid)?;
        Ok(Self(b))
    }
}
```
The `StringM<MAX>` type is designed to hold a vector of bytes with a maximum length specified by the constant `MAX`. However, the `from_str` implementation was simply wrapping the unescaped bytes in `Self(b)` without checking if the length of `b` exceeded `MAX`. This allowed the creation of a `StringM` instance that violated its own length invariant.

In the version after the commit:
```rust
impl<const MAX: u32> core::str::FromStr for StringM<MAX> {
    type Err = Error;
    fn from_str(s: &str) -> core::result::Result<Self, Self::Err> {
        let b = escape_bytes::unescape(s.as_bytes()).map_err(|_| Error::Invalid)?;
        b.try_into()
    }
}
```
The commit replaces `Ok(Self(b))` with `b.try_into()`. The `TryFrom<Vec<u8>>` implementation for `StringM<MAX>` (lines 2070-2081 in `before.txt`) correctly checks if the length of the vector is less than or equal to `MAX` and returns `Error::LengthExceedsMax` if it is not.

By adding this check, the commit fixes a vulnerability where an attacker could bypass length restrictions on `StringM` fields when they are deserialized or created via `FromStr` (e.g., through `serde`'s `DeserializeFromStr`). This is a classic case of failing to validate input length against a defined limit, which can lead to various issues depending on how the `StringM` is used later, including potential memory exhaustion or logic errors in systems that assume the invariant holds.
