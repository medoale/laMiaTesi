The code contains a critical vulnerability in `/work/modules/extras/extras.php`. Specifically, the `exec_ogp_module()` function processes a `$_POST['remove']` parameter that is passed directly to the `recursiveDelete()` function (defined in `/work/includes/helpers.php`).

The logic intended to prevent abuse is based on the existence of an `.nfo` file:
```php
$install_nfo = DATA_PATH . $folderToDelete . ".nfo";
if(file_exists($install_nfo)){
    unlink($install_nfo);
    $dirToDelete = $remove . "/" . strtolower($folderToDelete);
    if(file_exists($dirToDelete) && is_dir($dirToDelete)){
        recursiveDelete($dirToDelete);
    }
    // ...
}
```
However, the `$remove` variable is taken directly from `$_POST['remove']` without any validation or sanitization. An attacker who can upload or find a way to create a file in the `DATA_PATH` (which is `modules/[m]/data/`) can trigger the deletion of arbitrary directories on the filesystem by manipulating the `$remove` parameter (e.g., using directory traversal sequences like `../../`). Even if creating the `.nfo` file is difficult, the lack of sanitization on the path used for deletion constitutes a severe Arbitrary File Deletion vulnerability.

Furthermore, the `recursiveDelete` function itself uses `glob` and `unlink`/`rmdir` on the provided path, allowing for recursive deletion of any directory the web server has permissions to access, provided the `.nfo` check is bypassed or met.
