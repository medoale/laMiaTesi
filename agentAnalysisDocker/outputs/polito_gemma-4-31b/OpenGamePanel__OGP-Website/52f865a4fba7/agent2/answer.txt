The commit changes two files, `file_01` and `file_02`, in the same manner: it replaces the loose comparison operator `==` with the strict comparison operator `===` when comparing a hashed password (`md5($_POST['upassword'])` or `md5($password)`) with the stored password hash from the database (`$userInfo['users_passwd']`).

In PHP, loose comparison (`==`) can lead to security vulnerabilities known as "type juggling." If a password hash happens to start with "0e" followed only by digits (the "magic hash" problem), PHP treats it as scientific notation (0 raised to the power of something), which evaluates to 0. If both the calculated hash and the stored hash match this pattern, `0 == 0` evaluates to `true`, even if the actual strings are different. This allows an attacker to bypass authentication by providing a password that generates such a "magic hash."

By using strict comparison (`===`), PHP compares both the value and the type, ensuring that the strings must be identical and preventing the type juggling exploit.
