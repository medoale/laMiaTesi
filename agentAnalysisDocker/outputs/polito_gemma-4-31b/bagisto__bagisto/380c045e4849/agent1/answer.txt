**Before the commit:**
The code instantiated `MainSanitizer` and called `sanitize($dirtySVG)`. By default, many SVG sanitizers may allow certain external references or use defaults that are not strictly restrictive enough to prevent all forms of Server-Side Request Forgery (SSRF) or Cross-Site Scripting (XSS) via external entities.

**After the commit:**
The line `$sanitizer->removeRemoteReferences(true);` was added. 

According to the documentation of `enshrined/svg-sanitize`, the `removeRemoteReferences` method allows the developer to explicitly instruct the sanitizer to remove all remote references (such as external URLs in `<image xlink:href="...">`, `<style>`, etc.). Remote references in SVGs can be exploited for:
1. **SSRF (Server-Side Request Forgery):** If the server processes the SVG (e.g., for resizing or rendering), an attacker can use remote references to make the server perform requests to internal or external resources.
2. **XSS (Cross-Site Scripting):** If the SVG is served to a user, remote references can be used to load malicious scripts or external resources.

By explicitly enabling `removeRemoteReferences(true)`, the commit strengthens the sanitization process by eliminating a significant attack vector associated with external entities in SVG files. This is a security fix addressing potential SSRF and XSS vulnerabilities.
