The changes in `file_01` and `file_03` implement access control for the `/logger` endpoints. Specifically:

1.  **Broken Access Control Fix**: In `file_01`, `get_logger_config` and `update_logger_config` previously lacked any authentication or authorization checks. The commit adds `ActixAccess` and calls `access.check_global_access(...)`, ensuring that only authorized users can view or modify the logger configuration.
2.  **Arbitrary File Write/Overwrite Prevention**: In `update_logger_config`, the line `config.on_disk.log_file = None;` is added. This prevents an attacker with access to the endpoint from changing the log file path to an arbitrary location on the server's filesystem, which could lead to overwriting critical system files or performing a denial-of-service attack.
3.  **Authorization Mapping**: `file_03` updates the access control list (`ACTION_ACCESS`) to define the required permissions for these new checks.

The primary security vulnerability being addressed is the lack of access control on sensitive administrative endpoints, which falls under **CWE-285 (Improper Authorization)**. Additionally, the restriction on `log_file` specifically prevents a potential path traversal or arbitrary file write vulnerability via the configuration update.
