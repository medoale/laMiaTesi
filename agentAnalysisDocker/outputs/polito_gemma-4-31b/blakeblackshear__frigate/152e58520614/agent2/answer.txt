The analysis of the provided commit shows that it addresses several security vulnerabilities and implements security hardening across the authentication and user management systems.

### Vulnerabilities Addressed:

1.  **Improper Authentication / Broken Access Control (Password Change):**
    In the `update_password` function in `frigate/api/auth.py`, the original code allowed any authenticated user (including "viewers" as long as they target their own username) to change a password without providing the current (`old_password`) password. Additionally, an administrator could change any user's password without any verification of the current password. The fix introduces a requirement for the `old_password` when a user changes their own password or when a non-admin attempts a change, preventing account takeover if a session is hijacked.

2.  **Insufficient Password Strength:**
    The commit introduces `validate_password_strength`, which enforces minimum length (8 characters), uppercase letters, digits, and special characters. Previously, there were no server-side restrictions on password complexity.

3.  **Session Management / Insufficient Session Expiration:**
    The `refresh_time` in `AuthConfig` was reduced from 12 hours to 30 minutes, narrowing the window for session hijacking via stolen JWTs.

4.  **Lack of Session Invalidation after Password Change:**
    The commit adds a `password_changed_at` field to the `User` model. The `auth` function now checks if a JWT was issued before the last password change (`token_iat < password_changed_timestamp`). If so, the token is rejected and the session is invalidated, forcing a re-login. This is a critical fix for ensuring that stolen sessions cannot be used indefinitely after a password has been reset.

5.  **Insecure File Permissions:**
    The generation of the `.jwt_secret` file was updated to use `os.open` with `0o600` permissions (`-rw-------`), ensuring the secret is not world-readable on the filesystem.

6.  **Improper Authorization (Logout):**
    The `/logout` endpoint was changed from `allow_any_authenticated()` to `allow_public()`. While not a high-severity vulnerability, it ensures users can log out even if their session has already expired or is invalid.

### Classification:
The most significant fixes relate to **Broken Authentication** (CWE-287) and **Insufficient Session Expiration** (CWE-613), specifically regarding the lack of password verification during updates and the lack of session invalidation upon password change.
