The commit addresses a security vulnerability by moving a check for "Ferret expressions" to a point where it can actually be performed.

In `before.txt`, the code attempted to check for the "ferret expression" using `lasRequest.getProperty("ferret", "expression")` *before* the `lasRequest` object was initialized. Specifically:
- Line 368 (before): `String expression = lasRequest.getProperty("ferret", "expression");`
- Line 381 (before): `LASUIRequest lasRequest = new LASUIRequest();`

This would result in a `NullPointerException` at line 368, effectively bypassing the security check and potentially allowing "Ferret expressions" to be processed by the application if they were part of the XML request.

In `after.txt`, the check is moved *after* `lasRequest` has been instantiated and populated via `JDOMUtils.XML2JDOM(requestXML, lasRequest)`:
- Line 375 (after): `LASUIRequest lasRequest = new LASUIRequest();`
- Line 377 (after): `JDOMUtils.XML2JDOM(requestXML, lasRequest);`
- Line 380 (after): `String expression = lasRequest.getProperty("ferret", "expression");`

The intent of the check ("Ferret expressions are no longer allowed") strongly suggests that these expressions were previously identified as a security risk, likely enabling some form of Code Injection or Expression Language (EL) Injection. By ensuring the check is executed, the commit closes this vulnerability.

Since the check prevents the execution of potentially malicious expressions, this is a fix for an injection vulnerability.
