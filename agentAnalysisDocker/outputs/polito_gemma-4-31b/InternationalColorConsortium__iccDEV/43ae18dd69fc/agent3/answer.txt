Based on the security review of the provided repository, a vulnerability was found in `IccProfLib/IccIO.cpp`.

In the `CIccFileIO::Open` function, specifically on lines 444-452 (and similarly for the wide-character version on lines 464-473), the code attempts to ensure that the file access attribute string contains the character 'b' (for binary mode). If 'b' is missing, it constructs a new attribute string `myAttr` of fixed size 20.

```cpp
444:   char myAttr[20];
445: 
446:   if (!strchr(szAttr, 'b')) {
447:     myAttr[0] = szAttr[0];
448:     myAttr[1] = 'b';
449:     strcpy(myAttr+2, szAttr+1);
450:     szAttr = myAttr;
451:   }
```

The use of `strcpy` to copy the remainder of `szAttr` into `myAttr` without checking the length of `szAttr` can lead to a stack-based buffer overflow if `szAttr` is longer than 19 characters (including the null terminator). Since `szAttr` is a parameter to the `Open` function, which may be called with user-controlled input (depending on the higher-level application using this library), this represents a security risk.
