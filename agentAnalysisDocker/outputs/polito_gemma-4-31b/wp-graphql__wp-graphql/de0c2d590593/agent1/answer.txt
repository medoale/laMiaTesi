The provided changes are across two GitHub Actions workflow files. In both files, the commit replaces the direct interpolation of GitHub Actions expressions (e.g., `${{ github.event.inputs.redeploy_tag }}` or `${{ steps.plugin_info.outputs.version }}`) inside `run` shell scripts with a two-step process:
1. Mapping the GitHub expression to an environment variable in the `env:` block.
2. Referencing that environment variable within the shell script (e.g., `$REDEPLOY_TAG`).

This is a classic security fix for **Command Injection** in GitHub Actions. When `${{ ... }}` expressions are interpolated directly into a `run` block, they are substituted as plain text before the shell executes the script. If an attacker can control the value of the expression (for example, via a pull request title, a branch name, or a workflow input), they can inject arbitrary shell commands. By using environment variables, the values are passed to the shell as data, not as part of the command string, preventing the shell from interpreting special characters (like `;`, `&&`, or `` ` ``) as commands.

- `file_01`: `${{ github.event.inputs.redeploy_tag }}` $\rightarrow$ `REDEPLOY_TAG: ${{ github.event.inputs.redeploy_tag }}` and then using `$REDEPLOY_TAG`.
- `file_02`: `${{ github.event.pull_request.title }}` $\rightarrow$ `PR_TITLE: ${{ github.event.pull_request.title }}` and then using `$PR_TITLE`.
