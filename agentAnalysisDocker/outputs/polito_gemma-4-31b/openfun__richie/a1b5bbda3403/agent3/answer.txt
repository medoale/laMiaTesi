I have conducted a security review of the provided repository.

During my exploration, I analyzed the synchronization API in `src/richie/apps/courses/api.py` and the corresponding signature verification in `src/richie/apps/courses/utils.py`.

The API endpoint `sync_course_runs_from_request` verifies the authenticity of requests using an HMAC-SHA256 signature provided in the `Authorization` header. The verification is performed in `src/richie/apps/courses/api.py` at lines 256-259:

```python
    signature_is_valid = any(
        authorization_header == get_signature(message, secret)
        for secret in getattr(settings, "RICHIE_COURSE_RUN_SYNC_SECRETS", [])
    )
```

The `get_signature` function in `src/richie/apps/courses/utils.py` computes the HMAC and returns its hex digest.

The vulnerability lies in the use of the standard equality operator (`==`) to compare the provided `authorization_header` with the computed signature. In Python, the `==` operator for strings performs a lexicographical comparison that returns `False` as soon as a mismatching character is found. This introduces a timing side-channel, which allows an attacker to iteratively guess the correct signature by measuring the time the server takes to respond. This is a classic timing attack on MAC verification.

To prevent this, a constant-time comparison function such as `hmac.compare_digest()` should be used.
