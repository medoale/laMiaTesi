The commit introduces validation for DAG (Directed Acyclic Graph) file names in multiple parts of the application.

In `file_01`, a new middleware `validateDAGFileNameMiddleware` is added to the API routing. This middleware uses reflection to find a `FileName` field in the request object and validates it using `core.ValidateDAGName`.

In `file_04`, the `canonicalizeTopicIdentifier` function is updated to explicitly validate DAG identifiers for `TopicTypeDAG` and `TopicTypeDAGHistory` using the same `core.ValidateDAGName` function.

The tests added in `file_02` and `file_03` specifically target path traversal attempts, such as `..%2F..%2Ftmp%2Fsecret` and `../../tmp/secret.yaml`, and verify that these now result in errors (`http.StatusBadRequest` or a Go error).

By validating the `FileName` and identifiers to ensure they do not contain path traversal sequences (like `..`), the commit fixes a Path Traversal vulnerability, preventing attackers from accessing or manipulating files outside the intended directory.
