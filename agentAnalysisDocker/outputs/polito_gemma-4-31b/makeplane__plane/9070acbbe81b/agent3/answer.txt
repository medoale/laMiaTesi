The security review of the repository identified multiple instances where user-supplied input from query parameters is passed directly into Django's `.order_by()` method.

In several API endpoints, the `order_by` parameter is retrieved from the request using `request.GET.get("order_by", ...)` and then passed without validation to the `order_by()` method of a Django QuerySet. For example:

- In `/work/apps/api/plane/api/views/project.py`, line 181: `.order_by(request.GET.get("order_by", "sort_order"))`
- In `/work/apps/api/plane/api/views/issue.py`, lines 1656 and 1713: `.order_by(request.GET.get("order_by", "created_at"))`
- In `/work/apps/api/plane/api/views/module.py` and `/work/apps/api/plane/api/views/cycle.py`, the `order_by` variable is assigned from `request.GET.get` and subsequently passed to `.order_by(order_by)`.

While Django's `order_by()` provides some protection, passing unsanitized user input to it can lead to SQL injection in certain database backends or, more commonly, can be used for "blind" SQL injection through time-based attacks or by inducing database errors that reveal information about the schema or data. Specifically, in some Django versions and database configurations, this pattern allows attackers to inject expressions that can be used to extract sensitive data from the database.

This is a classic example of improper input validation leading to potential SQL injection.
