The commit removes a set of sanitization methods (`filter`, `sanitizeDotAttribute`, and `sanitizeAttributeValue`) and replaces the call to `filter(data)` with a direct pass of `data` to the Graphviz process. Crucially, it adds a check that explicitly returns `ImageDataSimple.ok()` (essentially skipping the Graphviz process) if the output format is SVG.

Looking at the removed `filter` method, it was attempting to prevent Cross-Site Scripting (XSS) in the generated Graphviz output by:
1. Replacing `javascript:` with `js:`.
2. Removing `<script>` tags.
3. Sanitizing specific Dot attributes (`fontname`, `label`, `xlabel`, `URL`, `href`, `tooltip`) by removing `<`, `>`, `"`, `'` and attributes starting with `on...=`.

These are classic, though often incomplete, "deny-list" based sanitization attempts to prevent XSS in SVG or HTML output generated by Graphviz. 

The "fix" in this commit is to simply **disable SVG output** in this particular code path (`PSystemDot`), as SVG is the primary vector for XSS in Graphviz output (since SVG is XML and can contain `<script>` tags or `onload` handlers). By returning `ImageDataSimple.ok()` when `fileFormat` is SVG, the code avoids passing potentially malicious data to Graphviz to create an SVG file that would then be served to a user.

This is a security fix because it eliminates the XSS attack vector by disabling the dangerous output format, rather than relying on the flawed regex-based sanitization.
