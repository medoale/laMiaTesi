The provided commit introduces granular settings for the "Amendments" feature in the Proposals component of the Decidim platform. Previously, the "Amendments" feature was either globally enabled or disabled for a component. The changes introduce three new step-level settings: `amendment_creation_enabled`, `amendment_reaction_enabled`, and `amendment_promotion_enabled`.

From a security perspective, the most significant change is in the authorization logic. In `Decidim::Amendable::Policy`, the `amend_action?` method was modified:


These changes implement a more restrictive and configurable access control model. By moving from a blanket `allow!` to checking specific component settings, the developers are ensuring that users can only perform these actions if the corresponding feature is explicitly enabled for the current component/step. This is a hardening measure that prevents unauthorized access to features that should be disabled.

While this is a security improvement (improving authorization granularity), it doesn't fix a specific, known vulnerability like a bypass or an injection. Instead, it implements the "Principle of Least Privilege" by allowing administrators to disable specific risky or unwanted functionalities.
