The analysis of the repository reveals several critical security vulnerabilities, primarily related to Command Injection.

In `work/trunk/web/admin/problem_add_loj.php` and `work/trunk/web/admin/problem_add_loj.php`, the application takes user-provided input (specifically `loj_id` from `$_POST['loj_id']`) and incorporates it directly into a system command without sufficient validation or sanitization. While `intval()` is used on `loj_id` in `problem_add_loj.php` (Line 59), other parts of the codebase exhibit much more dangerous patterns.

Specifically, in `work/trunk/web/admin/problem_import_hoj.php` and `work/trunk/web/admin/problem_import_qduoj.php`, the application processes ZIP files uploaded by the user. It extracts filenames from the ZIP archive and uses them to build commands that are then executed via `system()`.

In `work/trunk/web/admin/problem_import_hoj.php`:
- Lines 159-160: `array_push ($cmds,"mv $tempdir/$data_dir/* $OJ_DATA/$pid/");` and `array_push ($cmds,"rmdir $tempdir/$data_dir/");`.
- Line 177: `system($cmd);`.

The variable `$data_dir` is derived from the filename of a JSON file within the uploaded ZIP archive (`basename($file_name,".json")` at line 158). A malicious actor could upload a ZIP file containing a JSON file with a specially crafted name (e.g., `test;id; .json`), which would result in command injection when the `mv` or `rmdir` commands are executed.

Similar patterns are found in `work/trunk/web/admin/problem_import_qduoj.php` (Lines 156-157 and 174), where `$i` (an incrementing integer) is used, but the logic of extracting and using file paths from user-uploaded archives to construct shell commands is inherently dangerous.

These vulnerabilities allow an authenticated administrator (or anyone with the `problem_importer` privilege) to execute arbitrary commands on the server.
