The security review of the repository revealed a critical command injection vulnerability in the Android wrapper for `gpsd`.

In `/work/android/gpsd_wrapper.c`, the application retrieves a system property named `service.gpsd.parameters` using `property_get()`. It then performs a minimal transformation on this string, replacing commas with spaces:

```c
11: 	property_get("service.gpsd.parameters", gpsd_params, "-Nn,-D2,/dev/ttyACM0,/dev/ttyACM1");
12: 	while (gpsd_params[i] != 0){
13: 		if (gpsd_params[i] == ',') gpsd_params[i] = ' ';
14: 		i++;
15: 	}
```

Subsequently, this string is concatenated into a command buffer using `sprintf()` and executed via `system()`:

```c
17: 	sprintf(cmd, "/vendor/bin/logwrapper /vendor/bin/gpsd %s", gpsd_params);
...
21: 	system(cmd);
```

Because `gpsd_params` is taken directly from a system property and is not sanitized for shell metacharacters (such as `;`, `&`, `|`, `` ` ``, or `$()`), an attacker who can modify system properties (e.g., through a separate vulnerability, a malicious app with certain permissions, or a compromised system service) can inject arbitrary commands. For example, setting `service.gpsd.parameters` to `; /data/data/com.attacker/evil_script.sh ;` would result in the execution of the attacker's script with the privileges of the `gpsd_wrapper` process.

This is a classic example of OS Command Injection.

CWE_ID: CWE-78
CWE_NAME: Improper Neutralization of Special Elements used in an OS Command ('OS Command Injection')
