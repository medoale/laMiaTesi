The commit introduces a validation mechanism for filenames within ZIP archives. Specifically, it adds a function `validate_archive_member_name` that rejects filenames containing control characters (non-printable characters, matched by the regex `\p{C}`) or empty filenames.

This validation is integrated into the `unzip` functions (both streaming and seek-based), ensuring that archive members with "unacceptable" names are rejected before they are extracted. The commit also provides an escape hatch via an environment variable `UV_INSECURE_NO_ZIP_VALIDATION`.

This fix addresses a class of vulnerabilities where archives with specially crafted filenames containing control characters can cause unexpected behavior in different ZIP implementations or the operating system, potentially leading to issues like file system corruption, evasion of security checks, or other stability problems. In the context of ZIP archives, such "malformed" filenames are often used in "ZIP bomb" variants or other archive-based attacks to exploit discrepancies in how different tools handle non-printable characters in paths.

By enforcing a strict policy against control characters in filenames, the commit mitigates risks associated with improper input validation of archive member names.
