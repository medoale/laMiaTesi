The repository contains a security vulnerability where user-provided or configuration-defined JavaScript strings are passed directly to the JavaScript `eval()` function in the browser.

Specifically, in `Filament\Schemas\Components\Component::toSchemaHtml()` and `Filament\Schemas\resources\views\components\flex.blade.php`, the `getAfterStateUpdatedJs()` method returns an array of JavaScript strings. These strings are then rendered into the HTML within an `x-init` attribute, wrapped in a `$wire.watch()` call that executes them via `eval()`.

```php
// /work/packages/schemas/src/Components/Component.php:196
fn (string $js): string => '$wire.watch(' . Js::from($statePath) . ', ($state, $old) => isStateChanged($state, $old) && eval(' . Js::from($js) . '))',
```

Additionally, `Filament\Schemas\JsContent::toHtml()` explicitly uses `eval()` to render content:

```php
// /work/packages/schemas/src/JsContent.php:27
return <<<HTML
    <span x-text="() => eval({$content})"></span>
HTML;
```

If an attacker can influence the strings passed to `afterStateUpdatedJs()` or `JsContent::make()`, they can achieve Cross-Site Scripting (XSS). While these are often used by developers in configuration, if any part of these strings is derived from user-controlled input (e.g., through a dynamic form builder or a settings page that allows custom JS), it leads to a critical vulnerability.
