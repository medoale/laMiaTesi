The commit introduces a `strict_validation` parameter to the `AuthenticodeSignature.verify` method, which defaults to `True`. When `strict_validation` is enabled, it enforces checks on the certificate's `keyUsage` and `extendedKeyUsage` (EKU) extensions.

2. `extended_key_usage` (EKU) must be present and set (by setting `optional_eku=False`).

The update adds logic to only pass `key_usages` to the validator if the extension is present (or if it's not marked as critical and `optional_ku` allows it).

By enforcing `digital_signature` key usage and the `code_signing` EKU, the commit prevents the use of certificates issued for other purposes (e.g., email encryption) to sign code, which is a critical security check in PKI.
