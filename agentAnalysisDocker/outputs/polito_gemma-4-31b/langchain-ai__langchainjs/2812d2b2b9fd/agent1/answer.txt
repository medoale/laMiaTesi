The commit modifies the `RecursiveUrlLoader` in the `@langchain/community` package to prevent Server-Side Request Forgery (SSRF) vulnerabilities arising from HTTP redirects.

### Analysis:
1.  **Vulnerability**: Previously, `RecursiveUrlLoader` relied on the default `fetch` behavior for redirects. While it performed an initial validation of the starting URL using `validateSafeUrl`, it did not validate the URLs returned in `Location` headers during redirects. An attacker could provide a safe initial URL that redirects to a restricted internal resource (e.g., `http://127.0.0.1/admin` or cloud metadata services at `http://169.254.169.254`), bypassing the initial check.
2.  **Fix**: 
    -   The code now sets `redirect: "manual"` in the `fetch` options.
    -   It implements a manual redirect loop (up to `MAX_REDIRECTS = 10`).
    -   Crucially, it calls `validateSafeUrl(currentUrl, { allowHttp: true })` **inside the loop** for every redirect target before the request is made.
    -   This ensures that any redirect to a private IP or restricted range is caught and blocked, preventing SSRF.
3.  **Verification**: The added tests in `file_02` specifically verify that redirects to localhost, cloud metadata IPs, and private network ranges are blocked, while safe redirects are followed.

This is a classic fix for SSRF bypasses via redirects.
