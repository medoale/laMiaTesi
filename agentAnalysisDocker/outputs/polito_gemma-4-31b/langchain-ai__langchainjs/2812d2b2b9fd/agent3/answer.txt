The security review of the repository identified a critical SQL injection vulnerability in the `@langchain/google-cloud-sql-pg` package.

Specifically, in `libs/providers/langchain-google-cloud-sql-pg/src/vectorstore.ts`, the `PostgresVectorStore` class uses unsanitized string interpolation to construct SQL queries using the `tableName` and `schemaName` parameters.

For example, in the `initialize` method:
```typescript
const { rows } = await engine.pool.raw(
  `SELECT column_name, data_type FROM information_schema.columns WHERE table_name = '${tableName}' AND table_schema = '${schemaName}'`
);
```

And in the `isValidIndex` method:
```typescript
const stmt = `SELECT tablename, indexname
              FROM pg_indexes
              WHERE tablename = '${this.tableName}' AND schemaname = '${this.schemaName}' AND indexname = '${idxName}';`;
const { rows } = await this.engine.pool.raw(stmt);
```

Since these parameters are passed directly into the SQL query string without any sanitization or use of parameterized queries, an attacker who can control the `tableName` or `schemaName` (for instance, via a configuration file or an API endpoint that initializes the vector store) can execute arbitrary SQL commands on the underlying PostgreSQL database.

Additionally, other methods such as `dropVectorIndex` and `reIndex` also interpolate `idxName` (which is derived from `tableName`) directly into the query:
```typescript
const query = `DROP INDEX IF EXISTS ${idxName};`;
await this.engine.pool.raw(query);
```

While some identifiers are wrapped in double quotes in other parts of the code (e.g., `"${this.tableName}"`), the examples above show clear cases of single-quote interpolation for values and unquoted interpolation for identifiers, both of which are susceptible to SQL injection.

CWE_ID: CWE-89
CWE_NAME: Improper Neutralization of Special Elements used in an SQL Command ('SQL Injection')
