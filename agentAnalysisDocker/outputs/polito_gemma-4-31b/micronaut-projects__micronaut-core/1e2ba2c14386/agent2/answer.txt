The commit replaces a `ConcurrentHashMap` with a `ConcurrentLinkedHashMap` (with a maximum capacity of 100) in the `DefaultHtmlErrorResponseBodyProvider` class. This class caches generated HTML error response pages based on the `HtmlErrorPage` record, which includes the locale, HTTP status code, status reason, and a list of error messages.

In the original code, the `cache` was an unbounded `ConcurrentHashMap`. Because the `HtmlErrorPage` key includes a list of error messages (which can be derived from user-supplied input, as seen in the `error` method where `errorContext.getErrors()` are processed), an attacker could potentially trigger the creation of a large number of unique `HtmlErrorPage` objects by sending requests that result in different error messages. This would lead to the cache growing indefinitely, eventually consuming all available memory and causing a Denial of Service (DoS).

The fix introduces a maximum size for the cache (`MAX_CACHE_SIZE = 100`) using `ConcurrentLinkedHashMap`, which prevents unbounded memory growth.
