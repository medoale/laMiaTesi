The commit introduces a check to ensure that users who are not leaders of an event can only manage their own participation.

In the `before.txt` version:
The variable `$getUserUuid` was initialized at line 47:
`$getUserUuid = admFuncVariableIsValid($_GET, 'user_uuid', 'uuid', $gValidLogin ? array('defaultValue' => $gCurrentUser->getValue('usr_uuid')) : []);`
This allowed a logged-in user to provide any `user_uuid` via the `$_GET` parameter. If they provided a `user_uuid` belonging to another user, they could potentially modify that user's participation in an event (e.g., marking them as attending, cancelling their participation, or adding guests on their behalf), as long as the event was open for participation or the current user had some rights.

In the `after.txt` version:
A check is added at lines 417-419:
```php
        // if user is no leader of the event then only allow to handle their own participation
        if (!$participants->isLeader($gCurrentUserId)) {
            $getUserUuid = $gCurrentUser->getValue('usr_uuid');
        }
```
If the current user is not a leader of the event, `$getUserUuid` is forced to be the UUID of the currently logged-in user, ignoring any `user_uuid` provided in the `$_GET` request. This prevents an attacker from manipulating other users' participation data.

This is a classic Broken Access Control vulnerability, specifically an Insecure Direct Object Reference (IDOR), where a user-supplied identifier (`user_uuid`) was used to access/modify data without verifying if the requester had the authority to do so.
