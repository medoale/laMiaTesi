The provided changes implement a security fix to prevent Server-Side Request Forgery (SSRF) and potentially other vulnerabilities associated with processing remote documents.

The vulnerability existed in `DocumentUploadView.form_valid` (in `/work/geonode/documents/views.py`) and `BaseRemoteResourceHandler.create_geonode_resource` (in `/work/geonode/upload/handlers/common/remote.py`). In both cases, `resource_manager.set_thumbnail()` was called for documents regardless of whether they were local files or remote URLs.

Looking at the implementation of `create_document_thumbnail` in `/work/geonode/documents/tasks.py` (which is called by `resource_manager.set_thumbnail` for `Document` instances), the code retrieves the `doc_url` if provided and uses `default_storage_manager.open(doc_path)` to fetch the content of the remote URL. This allows an attacker to provide a malicious URL (e.g., pointing to internal network services or sensitive local files if the storage manager allows) and force the server to make a request to that URL in an attempt to generate a thumbnail.

The commit fixes this by adding checks to ensure that thumbnails are only generated for local documents. In `DocumentUploadView`, the call to `set_thumbnail` is now guarded by `if self.object.is_local:`. Similarly, in `BaseRemoteResourceHandler`, the thumbnail generation is skipped for remote resources.

This is a classic SSRF vulnerability where user-supplied input (the `doc_url`) is used in a server-side request without sufficient validation or restriction.
