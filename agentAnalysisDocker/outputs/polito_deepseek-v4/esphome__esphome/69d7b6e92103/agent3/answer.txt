### Finding: Web Server OTA Missing Authentication (CWE-306)

**Confirmed vulnerability — unreported, zero-day.**

| Aspect | Detail |
|---|---|
| **Vulnerability** | The on-device web server's OTA firmware update endpoint (`POST /update`) has **no authentication by default**. |
| **CWE** | **CWE-306: Missing Authentication for Critical Function** |
| **Impact** | **Remote Code Execution** on the microcontroller — any attacker on the local network can flash malicious firmware. |
| **Attack vector** | Network access to the device's web server port (default 80). |

#### Full attack chain:

1. ESPHome device configured with:
   ```yaml
   web_server:                    # no auth: sub-key = no authentication
     port: 80

   ota:
     - platform: web_server       # enables /update endpoint
   ```

2. `CONF_AUTH` in the `web_server` config schema is **optional** (no default):
   - `/work/esphome/components/web_server/__init__.py:189`: `cv.Optional(CONF_AUTH): cv.Schema({...})`
   - `/work/esphome/components/web_server/__init__.py:321-322`: `USE_WEBSERVER_AUTH` define added **only** if `CONF_AUTH` is present

3. `WebServerBase::add_handler()` applies `AuthMiddlewareHandler` **only** when `USE_WEBSERVER_AUTH` is compiled in:
   - `/work/esphome/components/web_server_base/web_server_base.cpp:17-20`:
     ```cpp
     #ifdef USE_WEBSERVER_AUTH
       if (!credentials_.username.empty()) {
         handler = new internal::AuthMiddlewareHandler(handler, &credentials_);
       }
     #endif
     ```

4. `OTARequestHandler` performs **no authentication at all**. Its `handleUpload()` method directly processes firmware data:
   - `/work/esphome/components/web_server/ota/ota_web_server.cpp:106-196` — accepts uploads, calls `ota_backend_->begin()`, `ota_backend_->write()`, `ota_backend_->end()` without any auth check.

5. Result: **Any unauthenticated POST to `/update` with a firmware binary achieves remote code execution.**

#### Evidence from code:

**`ota_web_server.cpp:106-196`** — `handleUpload()` directly processes OTA without any auth:
```cpp
void OTARequestHandler::handleUpload(AsyncWebServerRequest *request, const PlatformString &filename,
                                     size_t index, uint8_t *data, size_t len, bool final) {
  ota::OTAResponseTypes error_code = ota::OTA_RESPONSE_OK;
  if (index == 0 && !this->ota_backend_) {
    this->ota_init_(filename.c_str());
    this->ota_backend_ = ota::make_ota_backend();
    error_code = this->ota_backend_->begin(0);  // Starts flash write!
    ...
  }
  if (len > 0) {
    error_code = this->ota_backend_->write(data, len);  // Writes firmware!
    ...
  }
  if (final) {
    error_code = this->ota_backend_->end();  // Finalizes + reboots!
    ...
  }
}
```

**`ota_web_server.cpp:228`** — handler registered without explicit auth:
```cpp
base->add_handler(new OTARequestHandler(this));
```

**`web_server_base.cpp:17-20`** — auth only wraps if `USE_WEBSERVER_AUTH` is defined:
```cpp

  if (!credentials_.username.empty()) {
    handler = new internal::AuthMiddlewareHandler(handler, &credentials_);
  }
#endif
```

**`web_server/__init__.py:321-322`** — auth define only set if user configures it:
