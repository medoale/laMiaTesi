## Analysis Summary

### Vulnerability Found: CWE-134 — Use of Externally-Controlled Format String

**Location:** `/work/esphome/components/ezo_pmp/ezo_pmp.cpp`, line 404

```cpp
command_buffer_length = sprintf((char *) command_buffer, this->arbitrary_command_, this->next_command_duration_);
```

**How it works:**

1. The `exec_arbitrary_command(const std::string &command)` method (line 540) stores a raw C-string pointer from user-controlled YAML input into `this->arbitrary_command_`.
2. When the command is dispatched, `sprintf()` uses **this pointer directly as the format string**, not as a `%s` argument.
3. The destination buffer `command_buffer` is a stack-local `uint8_t[21]` (line 313) — only 21 bytes.

**Impact on the embedded device (ESP32/ESP8266):**

- An attacker who controls the YAML configuration (e.g., via supply-chain import from a compromised GitHub repo, or via the dashboard's config file editing API after authentication) can supply format specifiers such as `%x`, `%p`, `%n`, `%s` in the `arbitrary_command` value.
- **`%n` writes the number of bytes output so far to a memory address** — enabling arbitrary memory write.
- **`%x`/`%p`/`%s`** leak stack and memory contents (information disclosure).
- The 21-byte stack buffer can be overflowed, corrupting the stack.
- On embedded platforms with limited protections (ESP8266 has no ASLR), this can lead to arbitrary code execution on the device.

**The fix** is to pass the string as a `%s` argument instead of as the format string:
```cpp
sprintf((char *) command_buffer, "%s", this->arbitrary_command_);
```
