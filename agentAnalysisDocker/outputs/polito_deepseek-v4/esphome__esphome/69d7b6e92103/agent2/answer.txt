## Analysis Summary

**File changed:** `esphome/components/api/proto.cpp`

**The commit fixes 4 bounds-checks** across two methods (`count_repeated_field` and `decode`) in the protobuf decoding code, all with the same pattern:

### Before (vulnerable)
```cpp
if (ptr + field_length > end)     // pointer arithmetic, can wrap
if (ptr + 4 > end)                // same pattern
```

### After (fixed)
```cpp
if (field_length > static_cast<size_t>(end - ptr))  // size comparison, no wrap
if (end - ptr < 4)                                   // same safe approach
```

### Why this is a security vulnerability

**Root cause — CWE-190 (Integer Overflow or Wraparound):**

On all ESPHome target platforms (ESP32, ESP8266, RP2040, LibreTiny), pointers are 32 bits. The expression `ptr + field_length` performs pointer arithmetic where `field_length` is a `uint32_t` read from the protobuf message. An attacker can set this to a value near `UINT32_MAX` (e.g., `0xFFFF0000`). The addition wraps around on 32-bit pointer width, producing a result *smaller* than `end`. The bounds check `ptr + field_length > end` passes because the wrapped-around pointer is less than `end`.

**Consequence — CWE-125 (Out-of-bounds Read):**

After the bounds check is bypassed, `ptr += field_length` advances the pointer to the wrapped-around address. Subsequent code reads from that corrupted position:
- In `count_repeated_field`: the while-loop continues parsing field tags from the wrapped-around pointer — reading arbitrary memory.
- In `decode`: `ptr[3], ptr[2], ptr[1], ptr[0]` (for fixed32 fields) and `ProtoLengthDelimited(ptr, field_length)` (for length-delimited fields) read attacker-controlled offsets from arbitrary memory locations.

### Exploitability

This code processes incoming native API protobuf messages from the network. An attacker who can send messages to an ESPHome device (on the local network, or remotely if exposed) can craft a malicious protobuf message with a large length-delimited field size. This bypasses the bounds check, leads to out-of-bounds reads, and can leak sensitive data or cause a crash (DoS).

| **CWE-125** | Out-of-bounds Read | Consequence — reading memory outside the buffer after wraparound |

Both genuinely apply: CWE-190 describes *how* the check fails, and CWE-125 describes *what happens* as a result.
