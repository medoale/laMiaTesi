## Confirmed Vulnerabilities

### 1. Stored XSS via Public Intake Endpoint (CWE-79)
**File:** `/work/apps/api/plane/api/views/intake.py`, line 190-197  
The `IntakeIssueListCreateAPIEndpoint.post()` method creates an `Issue` directly via `Issue.objects.create()` without passing through any serializer that would call `validate_html_content()`. The `description_html` field at line 193 comes directly from user-supplied `request.data` and is stored raw. The Issue model's `save()` method (in `/work/apps/api/plane/db/models/issue.py`, lines 221-224) only calls `strip_tags()` to populate the `description_stripped` field — it does **not** sanitize or strip the raw `description_html`. This allows unauthenticated users to store arbitrary HTML/JavaScript that executes when an admin or member views the intake issue. The authenticated intake endpoints (in `/work/apps/api/plane/app/views/intake/base.py`) properly use `IssueCreateSerializer` which applies nh3 sanitization, making this omission in the public API endpoint a clear oversight.

### 2. Server-Side Request Forgery via Webhooks (CWE-918)
**File:** `/work/apps/api/plane/app/serializers/webhook.py`, lines 39-42; `/work/apps/api/plane/bgtasks/webhook_task.py`, line 329  
The webhook serializer only blocks loopback IPs (`127.0.0.1`, `::1`) but does **not** block private RFC 1918 ranges (10.x.x.x, 172.16-31.x.x, 192.168.x.x), link-local addresses, or cloud metadata IPs. Additionally, DNS resolution only happens at webhook creation time, not at execution time — enabling DNS rebinding attacks. The webhook task at line 329 sends `requests.post()` to the stored URL without re-validating the resolved IP.

### 3. Permissive CORS Policy with Credentials (CWE-942)
**File:** `/work/apps/api/plane/settings/common.py`, lines 120-128  
When `CORS_ALLOWED_ORIGINS` is not configured (the common case), `CORS_ALLOW_ALL_ORIGINS = True` with `CORS_ALLOW_CREDENTIALS = True`. Any website can make authenticated cross-origin requests to the API using the user's session cookies, enabling CSRF-style attacks.

### 4. Host Header Injection via Wildcard ALLOWED_HOSTS (CWE-345)
**File:** `/work/apps/api/plane/settings/common.py`, line 36  
`ALLOWED_HOSTS` defaults to `"*"` when the environment variable is unset. This allows any Host header, enabling cache poisoning, password-reset poisoning, and other host-based attacks.

### 5. Unauthenticated Access to Uploaded Files (CWE-200)
**File:** `/work/apps/api/plane/settings/common.py`, lines 249-250  
`AWS_DEFAULT_ACL = "public-read"` and `AWS_QUERYSTRING_AUTH = False` mean all uploaded file assets (avatars, attachments, etc.) are publicly accessible on S3 without any authentication checks, regardless of workspace/project membership.

### 6. IP Address Spoofing (CWE-290)
**File:** `/work/apps/api/plane/utils/ip_address.py`, lines 5-11  
The `get_client_ip()` function trusts the first value in the `X-Forwarded-For` header without any validation. Any client can spoof their IP address, undermining audit logs, rate limiting, and IP-based access controls.
