**Vulnerability: Missing Authorization in BCM ELOG PTA (`/work/core/pta/bcm/elog.c`)**

The Broadcom Error Log Pseudo Trusted Application registers itself with `PTA_DEFAULT_FLAGS` and **no `open_session_entry_point`**, meaning **any** TA in the system can open a session to it and invoke commands. The commands it exposes include:

1. **`PTA_BCM_ELOG_CMD_LOAD_NITRO_FW`** (cmd_id=3) - Writes caller-supplied data to secure physical memory at address `0x8ae00000 + 0x400 + caller_offset`. A malicious or compromised TA can overwrite Nitro firmware in secure RAM, leading to arbitrary code execution within the TEE.

2. **`PTA_BCM_ELOG_CMD_GET_NITRO_CRASH_DUMP`** (cmd_id=2) - Reads from secure physical memory region at `0x8b000000` up to 32MB, copying up to 1MB into the caller's buffer, enabling information disclosure from secure memory.

3. **`PTA_BCM_ELOG_CMD_GET_ELOG_MEM`** (cmd_id=1) - Reads from the error log memory region.

All three commands lack any per-caller authentication, access rights checking on the output buffer, or origin validation — they rely solely on the PTA being reachable. By contrast, other PTAs in the same codebase (e.g., `system.c`, `widevine.c`) implement `open_session_entry_point` with UUID whitelisting, and `system.c` explicitly uses `vm_check_access_rights(uctx, TEE_MEMORY_ACCESS_SECURE, ...)` to protect sensitive output buffers.
