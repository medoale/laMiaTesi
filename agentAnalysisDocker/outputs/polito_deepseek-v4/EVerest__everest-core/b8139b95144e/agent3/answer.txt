## Summary of Findings

After thorough exploration, I found **multiple security vulnerabilities** in this codebase. The most significant are:

### 1. CRITICAL: Command Injection via `os.system()` with f-string (CWE-78)

**File:** `/work/tests/ocpp_tests/test_sets/ocpp16/ocpp_compliance_tests.py` (line 6834)

```python
os.system(
    f"curl -T {Path(__file__).parent.parent / test_config.firmware_info.update_file} ftp://{getpass.getuser()}:12345@localhost:{ftp_server.port}"
)
```

The `test_config.firmware_info.update_file` and other interpolated values are passed directly into a shell command via f-string formatting. If any of these values contain shell metacharacters (spaces, semicolons, backticks, etc.), arbitrary command execution follows.

### 2. HIGH: TLS Server Starts with `SSL_VERIFY_NONE` — No Client Certificate Required (CWE-295)

**File:** `/work/lib/everest/iso15118/src/iso15118/io/connection_ssl.cpp` (line 278)

```cpp
SSL_CTX_set_verify(ctx, SSL_VERIFY_NONE, nullptr);
```

The ISO 15118-20 TLS server initializes with `SSL_VERIFY_NONE`. A `client_hello_cb` at line 280 switches to `SSL_VERIFY_PEER` only for TLS 1.3 clients. **TLS 1.2 clients can connect without any client certificate verification**, allowing an adversary to impersonate an EV and communicate with the charging station over a TLS connection without being authenticated.

This is compounded by:
- **`/work/modules/EVSE/EvseV2G/connection/tls_connection.cpp`** (line 281): `config.verify_client = false;`
- **`/work/modules/EVSE/IsoMux/connection/tls_connection.cpp`** (line 280): `config.verify_client = false;`

### 3. HIGH: MQTT Broker Allows Anonymous Access Without TLS (CWE-306, CWE-319)

**File:** `/work/applications/dev-environment/docker/images/mosquitto/mosquitto.conf` (lines 215, 514)

```
listener 1883
allow_anonymous true
```

The MQTT broker listens on TCP port 1883 with **no TLS** (no `certfile`/`keyfile` configured) and **allows anonymous unauthenticated connections**. Since all inter-module communication (including the API module that accepts control commands like `enable`, `disable`, `set_limit_amps`, `force_unlock`, etc.) flows over MQTT, any attacker on the network can:
- Publish arbitrary commands to any MQTT topic
- Subscribe to all telemetry/status data
- Control the EV charging station (start/stop charging, unlock connectors, set current limits)

### 4. MEDIUM: Controller WebSocket/HTTP Server Has No Authentication (CWE-306)

**File:** `/work/lib/everest/framework/src/controller/server.cpp` (line 144, 227, 231)

The admin/controller server uses `libwebsockets` on configurable port (default 8849) with:
- No `basic_auth_login_file` configured (line 144: `nullptr`)
- No TLS configured
- No origin validation on WebSocket connections
- All connections accepted unconditionally via `LWS_CALLBACK_ESTABLISHED`

This gives anyone who can reach port 8849 full admin access to the charging station's internal state and commands.

### 5. MEDIUM: Hardcoded Cryptographic Private Key Password (CWE-798)

**33 configuration files** across the codebase use `private_key_password: "123456"` — a trivially guessable password, effectively equivalent to no protection.

### 6. MEDIUM: Hardcoded Test Token (CWE-798)

**7 configuration files** use `token: DEADBEEF` as a default authorization token for charging. This is also the default in the `DummyTokenProvider` manifest.

### 7. MEDIUM: Shell Injection via shell script `eval` (CWE-77)

**File:** `/work/modules/Misc/Linux_Systemd_Rauc/diagnostics_collector.sh` (line 173)

```bash
eval "${1#--}=\"$2\""
```

User-supplied command-line arguments are directly passed to `eval`, allowing arbitrary shell command injection.

### 8. MEDIUM: Command Injection via `os.system()` with concatenation (CWE-78)

**File:** `/work/lib/everest/everest_api_types/tests/test_file_autogenerator/main.py` (line 32)

File paths concatenated into `os.system("clang-format -i " + ...)` without sanitization.

### 9. LOW: Command Injection via `subprocess.run(["sh", "-c", ...])` (CWE-78)

**File:** `/work/lib/everest/ocpp/src/code_generator/common/generate_cpp.py` (lines 668-674)

Path interpolated via `.format()` into a shell string passed to `sh -c`.
