### What changed across the four files

This is a coordinated security fix spanning **API route handling** and **SSE (Server-Sent Events) topic parsing** in what appears to be the [Dagu](https://github.com/dagu-org/dagu) workflow scheduler.

**file_01** — API handler (`api.go`)
- Added a new middleware `validateDAGFileNameMiddleware` that inspects every incoming API request via reflection, looks for a `FileName` field, and validates it with `core.ValidateDAGName()`.
- The middleware is now wired into the oapi-codegen strict handler (changed from `nil` middlewares to `[]api.StrictMiddlewareFunc{validateDAGFileNameMiddleware}`).
- Previously, DAG names from the URL path (e.g. `/api/v1/dags/{fileName}/spec`) were not validated — they went straight into file operations.

**file_02** — API test file
- Added `sendRawRequestStatus` helper that sends raw HTTP requests with `req.URL.RawPath` set, bypassing Go's default URL path normalization (preserving `%2F` as-is).
- Added `TestDAGFileNameRejectsEncodedTraversal` which sends requests like:
  - `GET /api/v1/dags/..%2F..%2Ftmp%2Fsecret/spec`
  - `DELETE /api/v1/dags/..%2F..%2Ftmp%2Fsecret`
  - `POST /api/v1/dags/..%2F..%2Ftmp%2Fsecret/start`
  - All expecting `400 Bad Request`.
- The existing `TestCreateNewDAGPathTraversal` test already tested unencoded traversal (`../../tmp/traversal`, `../escape`, etc.) in the request **body**, but the new test covers **URL-encoded path traversal in the URL path itself** — a different attack surface.

**file_03** — SSE test file
- Added `TestParseTopicRejectsDAGTraversalIdentifiers` testing that SSE topics with path traversal identifiers are rejected:
  - `dag:../../tmp/secret.yaml`
  - `daghistory:..%2F..%2Ftmp%2Fsecret.yaml`

**file_04** — SSE topic parsing (`sse/topic.go`)

- **After**: This is split into two cases:

  - `case TopicTypeDAGRun, TopicTypeStepLog, TopicTypeQueueItems, TopicTypeDoc:` remains without DAG-name validation (these topic types deal with different identifiers like run IDs or queue names that don't map to file paths).

### Security vulnerability assessment

**Yes, this commit fixes a security vulnerability.**

**Attack scenario (before the fix):**
1. An attacker sends `GET /api/v1/dags/..%2F..%2Ftmp%2Fsecret/spec` — because `%2F` is **not** decoded by Go's URL path router (it is URL-encoded, so it bypasses `path.Clean()` normalization), the raw path `../../tmp/secret` reaches the handler.
2. The handler uses this unsanitized path to read a DAG spec file, effectively reading `/tmp/secret.yaml` (or any file on the filesystem).
3. Similarly, `DELETE` and `POST` endpoints allow writing/modifying files outside the intended directory.
4. The SSE topic parser (`dag:../../tmp/secret.yaml`) would subscribe to events for a path-traversed identifier, enabling a secondary vector for information disclosure.

The fix validates all DAG names through `core.ValidateDAGName()` at two layers:
- API middleware (file_01) — catches URL-path-based traversal before it reaches any handler.
- Topic parser (file_04) — catches traversal in SSE subscription topics.

**CWE classification:**

The primary and most specific classification is **CWE-22: Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal')**. The entire change is about preventing `../` and URL-encoded `..%2F` sequences from escaping the intended DAG directory to read or write arbitrary files.
