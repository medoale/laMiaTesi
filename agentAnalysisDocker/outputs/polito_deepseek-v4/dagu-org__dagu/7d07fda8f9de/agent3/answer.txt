## Vulnerability Analysis Complete

After tracing the full attack chain from entry point to exploitation, here is the finding:

### Summary

**A design flaw in Dagu's eval pipeline enables OS Command Injection via user-supplied parameters.** The root cause is in `commandEvalOptions()` at `/work/internal/runtime/builtin/command/command.go:451-462`: it disables `ExpandEnv` for Unix shells (to avoid double `$VAR` expansion) but **never disables `Substitute`**. The `Substitute` option (default `true`) controls backtick/`$()` command substitution. User-supplied parameter values flow through the eval pipeline where the `substitute` phase runs shell command execution on ALL evaluated strings — including data that originated from untrusted input.

### Two Attack Vectors

1. **Webhook Trigger** (`POST /api/v1/webhooks/{dagName}`): A JSON payload becomes the `WEBHOOK_PAYLOAD` param. If a DAG step references `${WEBHOOK_PAYLOAD}` in a command, backtick commands embedded in the payload JSON are executed.

2. **ExecuteDAGRunFromSpec** (`POST /api/v1/dag-runs/from-spec`): An authenticated user provides an inline YAML spec with `command: echo ${user_param}` and params like `user_param=\`id > /tmp/pwn\``. The backtick command is executed during evaluation.

### Data Flow

```
User Input (webhook body / API params)
  → marshalWebhookPayload / raw params string
  → ResolveRuntimeParams → params loaded into EnvScope
  → evaluateCommandArgs (node.go:525) → EvalString (env.go:312) → eval.String (eval.go:32)
  → defaultPipeline.execute (pipeline.go:46)
    → phase: variables → ${PARAM} resolved to user value (containing backticks)
    → phase: substitute → backtick command executed via exec.CommandContext("sh", "-c", ...)
    → result: command output replaces backtick expression
  → final command passed to shell/exec.Cmd
```

### Missing Mitigations

- The `OnlyReplaceVars()` option exists (options.go:95-101) that correctly disables `Substitute` and defers shell vars, but it is **never used** by `commandEvalOptions()`.
- No input validation/sanitization of parameter values before eval pipeline processing.
- No allowlist or schema enforcement for legacy param values that enter the eval pipeline.

### Classification

**Primary:** CWE-78 (OS Command Injection) — arbitrary shell command execution via backtick substitution in user-supplied parameter values.
**Secondary:** CWE-20 (Improper Input Validation) — no validation of parameter values before eval pipeline processing.
