## Analysis

This commit spans 5 files that together fix **CVE-2026-34203**, a security vulnerability in the Nautobot application.

### What changed

The core fix is in **file_04** (a Django REST Framework serializer). Before the fix, the `UserSerializer.validate()` method handled password setup (setting unusable passwords when omitted, hashing when provided) but **never called Django's `validate_password()` function**. After the fix:

1. A new import: `from django.contrib.auth.password_validation import validate_password`
2. In the `validate()` method, after the `if mock_password:` block, an `elif` clause was added that calls `validate_password(validated_data["password"], user=self.instance)` whenever a real password is present in the input.

**file_01** documents the fix in release notes.
**file_02** adds `AUTH_PASSWORD_VALIDATORS` to the Nautobot settings JSON schema (making the configuration option visible).
**file_03** logs the new CVE entry in the security notices page.
**file_05** adds two test methods that verify weak passwords are now rejected when `AUTH_PASSWORD_VALIDATORS` is configured.

### The vulnerability

The REST API endpoints for creating and updating users bypassed any password strength rules configured via Django's `AUTH_PASSWORD_VALIDATORS`. An attacker who obtained the ability to create or modify users via the API (e.g., an admin user) could set arbitrarily weak passwords (e.g., `"pass"`, `"1234"`), undermining the organization's password policy. This could then be leveraged in a downstream attack (e.g., password guessing/brute-force against those accounts).

### CWE classification

The most specific and accurate CWE is **CWE-521: Weak Password Requirements**. The software failed to enforce configured password strength rules (validators) when processing user creation and modification through the REST API, allowing weak passwords to be set in violation of policy.

**CWE-20: Improper Input Validation** is a broader category that also applies tangentially (the password was not validated before being accepted), but CWE-521 is far more specific to password weakness and is preferred here.
