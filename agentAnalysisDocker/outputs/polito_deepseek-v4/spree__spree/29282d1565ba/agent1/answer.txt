### Vulnerability Found: YES

This commit fixes a security vulnerability in the Spree e-commerce platform's `Order::AddressBook` module.

### What the code does

The code manages billing/shipping address assignment on orders. The `bill_address_id=` and `ship_address_id=` setter methods look up an `Address` by the given `id`, then check `address.user_id == user_id` to verify the current user owns that address before assigning it.

### The vulnerability

**Before the fix:**

```ruby
if address && address.user_id == user_id
```

When the order has a **guest user** (i.e. `user_id` is `nil`), the comparison `address.user_id == nil` succeeds for **any address whose `user_id` is also `nil`** (because `nil == nil` evaluates to `true` in Ruby). This means an unauthenticated guest user could:

1. Know or guess an address ID belonging to another guest user
2. Pass that `bill_address_id` (or `ship_address_id`) via the API
3. Have that address assigned to their order — effectively **stealing another guest user's address data**

This is an **Insecure Direct Object Reference (IDOR)** vulnerability: the user controls the address record key, and the authorization check is incomplete because it doesn't verify the user is authenticated before comparing user IDs.

### The fix

The critical change is adding `user_id.present?` to the guard condition:

```ruby
if address && user_id.present? && address.user_id == user_id
```

For guest users (`user_id` is `nil`), `user_id.present?` short-circuits to `false`, so the else branch runs and `bill_address_id`/`ship_address_id` is unconditionally set to `nil`. Authenticated users still pass through the ownership check as before.

The same fix is applied symmetrically to both `bill_address_id=` and `ship_address_id=`.

### Supporting evidence

- **file_03** (spec tests) adds explicit test cases: "when assigned address does not belong to user" expects the address to be set to nil, and "with guest user ... when assigning a different existing address" also expects nil.
- **file_01** (controller specs) verifies that guest users **cannot** bind an address belonging to another user, confirming this was previously a bypass vector.
