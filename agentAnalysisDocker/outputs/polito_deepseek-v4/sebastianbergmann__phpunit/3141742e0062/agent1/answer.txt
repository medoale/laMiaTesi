## Analysis

This commit adds a security check to PHPUnit 8.5.52 that prevents **Poisoned Pipeline Execution (PPE) attacks**.

### What changed

**`file_02` (the core code — `PhptTestCase.php`):**
- A new private method `ensureCoverageFileDoesNotExist()` was added to the `PhptTestCase` class.
- It is called in the constructor right after `$this->filename` is set, before any test execution.
- The method computes the expected coverage file path (via the existing `getCoverageFiles()` method) and throws an `Exception` if that file already exists on disk.

**`file_01` (CHANGELOG):** Documents that this change is explicitly to prevent *Poisoned Pipeline Execution (PPE) attacks using prepared `.coverage` files in pull requests*.

### Why this is a security fix

The attack scenario is a **CI/CD supply chain attack**:

1. PHPUnit PHPT tests write code coverage data to a `.coverage` file whose path is deterministically derived from the test filename (via `getCoverageFiles()`).
2. After the test job runs, the `cleanupForCoverage()` method reads and **`unserialize()`s** the contents of that `.coverage` file using `@unserialize($buffer, ['allowed_classes' => false])`.
3. An attacker who submits a pull request can include a pre-crafted `.coverage` file at the same predictable path in the source tree.
4. If the CI pipeline runs the PHPT test with code coverage enabled, the pre-existing attacker-controlled file would be deserialized — a **PHP Object Injection** attack.

While `allowed_classes => false` limits exploitation to `__PHP_Incomplete_Class` objects, the unserialization of attacker-controlled data still presents a risk (e.g., triggering `__wakeup()`, `__destruct()`, or `__unserialize()` magic methods on objects whose classes may be autoloaded). Moreover, the **predictable file path** combined with **inclusion of files from an untrusted source** in a privileged CI/CD pipeline is the core supply-chain weakness.

### CWE Classification

Two CWEs genuinely apply:

1. **CWE-829: Inclusion of Functionality from Untrusted Control Sphere** — The CI/CD pipeline was potentially including and executing code (via `unserialize()`) from a `.coverage` file that originated from an untrusted source (a PR fork's file tree). This is the canonical classification for Poisoned Pipeline Execution attacks.

2. **CWE-502: Deserialization of Untrusted Data** — The concrete exploitation mechanism is PHP `unserialize()` of attacker-controlled data. The fix prevents attacker-supplied coverage files from reaching the deserialization point at all.
