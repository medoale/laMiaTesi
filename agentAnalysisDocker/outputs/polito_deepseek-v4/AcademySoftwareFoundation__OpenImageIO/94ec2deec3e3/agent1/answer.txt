## Analysis

This commit changes the OpenImageIO DDS image format plugin (`ddsinput.cpp`/`dds_pvt.cpp`). The DDS file header contains attacker-controlled width, height, depth, and bits-per-pixel values. The original code uses `unsigned int` (32-bit) and `int` for size/offset calculations involving these values, which is the root cause.

### Primary change: Integer overflow prevention (CWE-190)

1. **`internal_seek_subimage` — offset calculation**: Variables `ofs` and `len` were `unsigned int` (32 bits). The expression `len = w * h * d * m_Bpp` multiplies attacker-controlled values; on a 32-bit `unsigned int`, this overflows easily (e.g., 16384×16384×8×4 = 8 GB, far exceeding 2³²). An overflow causes `ofs` to wrap to a small value, so `ioseek(ofs, SEEK_SET)` seeks to the wrong file location. Subsequent `ioread` then reads data from the wrong offset into a heap buffer, causing **heap corruption** (read of unintended data / write past allocated bounds).

2. **`read_native_scanline` — buffer offset calculation**: The original code computes the offset inline as `z * m_spec.height * size + y * size` using `int` arithmetic. If overflow occurs, the resulting offset can be negative or wrong, causing `memcpy` to read from an arbitrary memory location relative to the buffer (out-of-bounds read), which can leak information or lead to further corruption.

3. **Other type widening**: All dimension parameters (`w`, `h`, `d`) and loop counters in `internal_readimg` and `seek_subimage` are changed from `int`/`unsigned int` to `size_t` (typically 64 bits), eliminating the overflow risk in multiplication chains.

### Secondary change: Resolution bounds validation (CWE-770)

New `check_open()` calls reject cube maps, volumes, and 2D textures with dimensions exceeding defined limits (16384, 4096, 32768 respectively), preventing allocation of excessively large buffers from crafted files — a denial-of-service / resource exhaustion vector.

### Classification

The core fix is **integer overflow** that leads to heap memory corruption. The added bounds checks are a secondary hardening measure. The most specific and accurate CWE is **CWE-190**.
