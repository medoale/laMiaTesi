### Confirmed Issues (none exploitable in current code):

1. **`Filesystem::read_text_from_command()`** (`filesystem.cpp:670-702`): Public API that passes arbitrary string to `popen()`. Design weakness — no in-tree callers pass user input.

2. **IFF parser integer overflow** (`iff_pvt.h:87`): `image_bytes()` computes `pixel_bytes() * width * height` without overflow check. Only exploitable on **32-bit platforms** where `size_t` overflow is practical. On 64-bit, dimensions from IFF file (uint32) with pixel_bytes ≤ 6 cannot overflow 64-bit.

3. **TIFF `uncompress_one_strip` COMPRESSION_NONE path** (`tiffinput.cpp:589`): `memcpy(uncompressed_buf, compressed_buf, csize)` with no check that `csize <= strip_bytes`. However, this function is only called from paths that require `COMPRESSION_ADOBE_DEFLATE` — the `COMPRESSION_NONE` branch is dead code.

4. **TGA RLE decoder** (`targainput.cpp:754-806`): Nested `y--` in inner packet loop while outer loop also decrements `y`, causing scanline skipping. Bounds checking prevents underflow. Logic bug, not memory safety.
