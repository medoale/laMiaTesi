## Security Audit Report - LangChain.js

### Summary of Findings

I conducted a comprehensive security audit of the LangChain.js codebase, examining SQL injection, command injection, XSS, code injection, deserialization, and SSRF attack surfaces. Below are the key findings, ordered by severity.

### 🔴 VULNERABILITY FOUND: Filter Injection in VectaraTranslator

**Location**: `/work/libs/langchain-community/src/structured_query/vectara.ts`, line 32

**The Bug**:
```typescript
function processValue(value: Value): string {
  /** Convert a value to a string and add single quotes if it is a string. */
  if (typeof value === "string") {
    return `'${value}'`;   // <-- No escaping of single quotes within value
  } else {
    return String(value);
  }
}
```

The function wraps string values in single quotes but performs **no sanitization** of the value itself. If the value contains a single quote (`'`), it breaks out of the string literal, enabling filter injection.

Used at line 119:
```typescript
return `( doc.${comparison.attribute} ${comparator} ${processValue(comparison.value)} )`;
```

Both `comparison.attribute` and `comparison.value` are interpolated without sanitization.

**Attack Flow**:
1. User crafts a malicious natural language query (e.g., "Find documents where price = ' ) OR 1=1 --")
2. The `SelfQueryRetriever` (at `/work/libs/langchain-classic/src/retrievers/self_query/index.ts`) passes this to an LLM-based query constructor
3. Through prompt injection, the LLM generates a `StructuredQuery` with a filter value containing single quotes
4. `VectaraTranslator.visitComparison()` builds a filter string using `processValue()` which fails to escape internal quotes
5. The resulting malformed filter string is passed to the Vectara vector store query
6. This allows manipulation of the Vectara filter syntax — data exfiltration, filter bypass, or denial of service

**CWE**: CWE-89 (Improper Neutralization of Special Elements used in an SQL Command / Filter Injection)
**Severity**: High (CVSS ~8.2)

**Primary Vulnerability**: **VectaraTranslator `processValue()` — Filter Injection**

The most impactful zero-day vulnerability is in the Vectara structured query translator, where the `processValue()` function wraps string values in single quotes without escaping internal single quotes. Since the values flow from LLM-parsed user queries through the `SelfQueryRetriever` → `VectaraTranslator` → `VectaraStore` pipeline, an attacker can exploit prompt injection to embed a malicious filter value containing a single quote, breaking out of the string literal and injecting arbitrary filter syntax into the Vectara query.

This is distinct from the other SQL-injection-like findings listed above because:
1. It is a **bug** (not a designed interface like `whereStr`)
2. It has a clear data flow from user input through the LLM to the injection sink
3. It is not documented or warned about
4. It enables filter manipulation, data exfiltration, and potentially broader injection attacks
