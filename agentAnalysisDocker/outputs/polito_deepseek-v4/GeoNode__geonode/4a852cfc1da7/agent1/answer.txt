Thumbnail generation is now **skipped** for remote documents (those whose `doc_url` points to an external URL).

## Security Assessment

The production code change in **File 02** fixes a **Server-Side Request Forgery (SSRF)** vulnerability.

**How it worked before:** When a user uploaded a "document" by providing a remote URL (e.g., `http://malicious-site.com/...` or `http://169.254.169.254/latest/meta-data/`), the `DocumentUploadView.form_valid` method would call `resource_manager.set_thumbnail(...)`. The thumbnail generation logic would attempt to **fetch** the content at the user-supplied URL in order to generate a thumbnail image. This means the server would make an outbound HTTP request to an attacker-controlled or attacker-chosen destination.

**What an attacker could do:**
- Probe internal network services behind a firewall (e.g., `http://localhost:9200` for Elasticsearch, `http://localhost:5432` for Postgres status pages, etc.)
- Access cloud metadata endpoints (e.g., `http://169.254.169.254/latest/meta-data/` on AWS/GCP/Azure) to steal cloud credentials
- Use the server as a proxy to attack other internal systems

**Impact:** High — an unauthenticated or low-privileged user could trigger the server to make requests to internal services, potentially leaking sensitive cloud infrastructure credentials or pivoting to attack internal services.

**The fix:** By checking `self.object.is_local` before calling `set_thumbnail`, the server no longer makes outbound HTTP requests for remote URLs. The thumbnail generation is now restricted to documents whose files are actually uploaded to the server (local files), which is a safe operation.
