The file in question is `PSystemDot.java`, which handles "direct DOT" diagrams — PlantUML's feature that passes raw Graphviz DOT language input directly to Graphviz for rendering.

**What the commit does:**
1. **Removes** the entire `filter()` method (and its helpers `sanitizeDotAttribute`, `sanitizeAttributeValue`) which attempted regex-based sanitization of DOT input
2. **Removes** imports for `Matcher` and `Pattern`
3. **Adds** an early return for SVG format: `if (fileFormat.getFileFormat() == FileFormat.SVG) return ImageDataSimple.ok();`
4. **Changes** from `createForSystemDot(null, filter(data), ...)` to `createForSystemDot(null, data, ...)` — passes raw data for non-SVG formats

**Why this is a security fix (CWE-79 — Cross-Site Scripting):**

The `before` code attempted to sanitize DOT input to prevent XSS in SVG output, but the sanitization was fundamentally broken:

1. **`javascript:` filtering** — uses `\bjavascript:` which only catches a literal scheme prefix. Bypassable with `java\nscript:`, HTML entities (`&#106;avascript:`), `data:` URIs, etc.
2. **Attribute regex** — `Pattern.compile("(?i)(" + attrName + ")\\s*=\\s*\"([^\"]*)\"")` only matches double-quoted attributes. Misses `attr='value'` and `attr=value` forms.
3. **Limited attribute coverage** — only `fontname`, `label`, `xlabel`, `URL`, `href`, `tooltip`. Misses SVG-specific attributes like `xlink:href`, which Graphviz can emit.
4. **Event handler stripping** — `on[a-z]+\s*=` is narrow and can be bypassed with whitespace variations or Unicode tricks.
5. **Only scratches the surface** — Graphviz renders DOT to SVG, where many injection vectors exist beyond these specific patterns.

The correct fix: Graphviz (both native and VizJs) renders user-supplied DOT attribute values directly into SVG elements. Since SVG is an interactive format that supports JavaScript execution (via `<script>`, event handlers, `javascript:` URLs in `<a>` elements, etc.), and the filter approach is fundamentally insufficient to cover all XSS vectors, the safest mitigation is to **not produce SVG output from the direct DOT feature at all**.

This commit fixes a stored/reflected Cross-Site Scripting vulnerability where an attacker could craft DOT input that, when rendered to SVG and viewed in a browser, executes arbitrary JavaScript in the security context of the hosting application.
