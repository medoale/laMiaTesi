## Analysis

**What changed:**
The commit removed the entire `filter()` method and its helper methods (`sanitizeDotAttribute`, `sanitizeAttributeValue`) from `PSystemDot.java`. These methods were performing input sanitization of user-supplied data (dot/graphviz diagram source) before passing it to the Graphviz rendering engine. Specifically, the sanitization was:
1. Replacing `javascript:` with `js:` (to prevent javascript: URIs)
2. Removing `<script>` tags (to prevent script injection)
3. Sanitizing several dot attributes (`fontname`, `label`, `xlabel`, `URL`, `href`, `tooltip`) by stripping `<`, `>`, `"`, `'` and event handler attributes like `onclick=`

**What was added:**
- An early return for SVG file format: `if (fileFormat.getFileFormat() == FileFormat.SVG) return ImageDataSimple.ok();`
- The `filter(data)` call was removed — the raw `data` is now passed directly to Graphviz

This looks like a **defense removal** — the sanitization was ripped out entirely. The SVG early return seems like a misguided attempt to address SVG-based injection by simply refusing to generate SVG output, but it's not a proper fix. The proper fix would have been to keep the sanitization (or improve it) and still allow SVG generation.

**Is this a security vulnerability fix?**

No — this is the opposite. This commit **removes** existing security sanitization defenses. The `filter()` method was a defense-in-depth measure preventing injection attacks (like XSS via SVG output or malicious Graphviz attribute injection). By removing it, the code becomes **more vulnerable**, not less.
