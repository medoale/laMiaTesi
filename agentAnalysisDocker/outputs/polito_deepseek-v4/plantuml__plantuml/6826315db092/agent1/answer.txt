Now let me carefully analyze the before, after, and diff files for this single commit.

**The code:** `PSystemDot.java` from PlantUML — a DOT/Graphviz diagram renderer.

**Before the commit:**
- The `exportDiagramNow` method calls `filter(data)` on the DOT input before passing it to Graphviz.
- The `filter()` method attempts to sanitize the DOT data: replaces `javascript:` with `js:`, strips `<script>` tags, and sanitizes attributes (`fontname`, `label`, `xlabel`, `URL`, `href`, `tooltip`).
- The `sanitizeDotAttribute` method uses a regex with `Matcher.appendReplacement(sb, m.group(1) + "=\"" + safeValue + "\"")` where `safeValue` comes from user-controlled DOT data.
- `sanitizeAttributeValue` strips `<`, `>`, `"`, `'`, and `on<event>=` patterns, but **does not** sanitize `$` or `\` characters.

**The vulnerability:**
`Matcher.appendReplacement` in Java interprets `$` as back-reference prefixes and `\` as escape characters in the replacement string. Since `safeValue` passes through `sanitizeAttributeValue` unmodified for `$` and `\`, a DOT attribute value like `label="foo$1bar"` would cause `appendReplacement` to interpret `$1` as a reference to capture group 1 — potentially corrupting the output, enabling bypass of the sanitization, or causing runtime exceptions. This is a well-documented anti-pattern in Java's regex API (`java.util.regex.Matcher.appendReplacement`). The correct approach would have been `Matcher.quoteReplacement(safeValue)`.

**After the commit:**
- The entire `filter()`, `sanitizeDotAttribute()`, and `sanitizeAttributeValue()` methods are **removed**.
- An early return is added for SVG output format (`if (fileFormat.getFileFormat() == FileFormat.SVG) return ImageDataSimple.ok();`).
- For non-SVG formats, `data` (the raw DOT input) is passed directly to Graphviz without any sanitization.

**Why this fixes a vulnerability:**
The broken `appendReplacement` call meant that `$` and `\` in user-controlled DOT attribute values were interpreted as regex metacharacters in the replacement string, not as literal characters. This could be exploited to bypass the intended sanitization (e.g., smuggling `javascript:` or `onclick=` through despite the filter) because the replacement string could produce arbitrary output. By removing the flawed sanitization entirely and short-circuiting SVG output (the only format where XSS is relevant), the vulnerability is eliminated.

Most specific CWE: **CWE-838** (Inappropriate Encoding for Output Context) — the output context is `Matcher.appendReplacement`, which treats `$` and `\` specially, but the code failed to encode/escape the user-controlled value for that context using `quoteReplacement()`.
