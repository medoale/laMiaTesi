## Vulnerability Analysis

### 1. CWE-494: Download of Code Without Integrity Check

The Notepad++ auto-updater path downloads an executable (`.exe`) from a URL provided by the remote update server's XML response and executes it with **no cryptographic signature or hash verification**.

At **line 1569** in `src/winmain.cpp`:
```cpp
bool dlSuccessful = downloadBinary(gupDlInfo.getDownloadLocation(), dlDest, L"", ...);
```

The third argument (`L""`) is the SHA-256 hash — it is **empty**. Inside `downloadBinary()` (line 882–928), this empty string causes the entire hash-verification block to be skipped:
```cpp
if (!sha2HashToCheck.empty())   // ← false when L""
```

The downloaded file is then executed via `runInstaller()` → `ShellExecute(NULL, L"open", app2runPath.c_str(), ...)` (line 1036). An attacker who can intercept the network response (MITM, compromised CDN, or compromised update server) can inject a malicious `<Location>` URL and have arbitrary code executed on every user's machine.

> By contrast, the plugin-updater code path **does** pass a 64-character SHA-256 hash and verifies it, so the vulnerability is specific to the main Notepad++ auto-update flow.

### 2. CWE-346: Origin Validation Error

The `forceDomain` mechanism (lines 1474–1490) is intended to restrict download URLs to a trusted domain, but it uses a **simple prefix match** instead of proper domain-name component parsing:

```cpp
if (downloadURL.compare(0, forceDomain.size(), forceDomain) != 0)
```

If `forceDomain` is `https://notepad-plus-plus.org`, a URL like `https://notepad-plus-plus.org.evil.com/payload.exe` passes validation because it also starts with that string. This makes the security mechanism trivially bypassable.

### 3. CWE-22: Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal')

The `decompress()` function (lines 384–502 of `winmain.cpp`) extracts zip archives using zip entry filenames from `entry->GetFullName()` without any validation for path-traversal sequences (`../`, `..\\`, or absolute paths like `C:\`):

```cpp
wstring file2extrait = s2ws(entry->GetFullName());
wstring extraitFullFilePath = unzipDestTo;
PathAppend(extraitFullFilePath, file2extrait);
// ...
destFile.open(extraitFullFilePath, std::ios::binary | std::ios::trunc);
```

The `IsValidFilename()` function in `ZipArchiveEntry.cpp` only checks that the entry name is not all `/` characters — it does **not** check for `..` or absolute paths. A malicious plugin zip (whose SHA-256 could be spoofed, or which passes a faked hash) could write files to arbitrary locations on disk.
