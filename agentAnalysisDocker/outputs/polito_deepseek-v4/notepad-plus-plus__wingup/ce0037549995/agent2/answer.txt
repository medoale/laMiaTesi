## Security Analysis

### What the commit does

This commit adds **Authenticode code signing verification** to the GUP (Generic Updater for Notepad++) tool. Specifically:

1. **Creates `verifySignedfile.cpp` / `verifySignedfile.h`** — A new `SecurityGuard` class that verifies the Authenticode signature of a downloaded binary, checking trust chain, certificate revocation status, display name, subject, key ID, and authority key ID.

2. **Creates `Common.cpp` / `Common.h`** — Utility functions (`s2ws`, `ws2s`, `GetLastErrorAsString`, etc.) previously duplicated in multiple files, moved to a shared location. The `s2ws`/`ws2s` implementation also switches from the deprecated `std::codecvt_utf8` to the native Windows API (`MultiByteToWideChar`/`WideCharToMultiByte`).

3. **Modifies `winmain.cpp`** — Adds new command-line flags (`-chkCertSig=yes`, `-chkCertTrustChain`, `-chkCertRevoc`, `-chkCertName=`, `-chkCertSubject=`, `-chkCertKeyId=`, `-chkCertAuthorityKeyId=`, `-infoUrl=`, `-forceDomain=`). After the binary is downloaded, if `-chkCertSig=yes` was passed, the tool now verifies the binary's Authenticode signature before executing it. If verification fails, the tool returns `-1` and does **not** execute the binary.

4. **Modifies `gup.rc` / `resource.h`** — Adds the new command-line help dialog (`IDD_COMMANDLINEARGSBOX`).

5. **Modifies `gup.vcxproj` / `gup.vcxproj.filters`** — Adds the new `.cpp`/`.h` files to the build and links `Crypt32.lib`, `wintrust.lib`, `Sensapi.lib`.

### Security vulnerability being fixed

**Before this commit:**
- The GUP updater downloads an `.exe` binary from a remote URL and immediately executes it via `ShellExecute`.
- There is **no cryptographic verification** of the downloaded binary. The SHA-256 hash check (present for plugin `.zip` downloads) is **not** applied to the main `.exe` updater — the `sha2HashToCheck` parameter is passed as an empty string `L""` at line 1569 of the old `winmain.cpp`.
- The only safeguard is the `forceDomain` prefix check, which verifies the *download URL* matches a pattern — it does nothing to verify the *binary content*.

**After this commit:**
- When the command-line flags are set, the downloaded binary's Authenticode digital signature is verified before execution.
- Verification can cover: trust chain validity, certificate revocation status, and identity checks (display name, subject, key ID, authority key ID).
- If verification fails, the binary is **not executed**.

### CWE Classification

This commit fixes a security vulnerability where a downloaded binary was executed without verifying its cryptographic signature. The most applicable CWEs are:

- **CWE-347 (Improper Verification of Cryptographic Signature)** — The fix adds Authenticode cryptographic signature verification that was previously absent. Before the fix, no cryptographic check was performed on the downloaded executable before execution.

- **CWE-494 (Download of Code Without Integrity Check)** — The updater downloads executable code and runs it without any integrity verification. The fix addresses this by adding signature verification.

CWE-347 is the most specific and precise classification since the commit specifically adds cryptographic signature verification (Authenticode on Windows), which is exactly what that CWE describes.
