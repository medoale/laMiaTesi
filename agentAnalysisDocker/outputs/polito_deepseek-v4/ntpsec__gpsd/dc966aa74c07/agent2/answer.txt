## Analysis

The commit modifies a single file: **`/work/drivers/driver_nmea2000.c`** — the NMEA2000-over-CAN driver for GPSD. The critical security change is in the function `hnd_129540()`, which handles **PGN 129540 "GNSS Satellites in View"** messages arriving over the CAN bus from arbitrary nearby devices.

### The vulnerable code (before the fix)

```c
session->gpsdata.satellites_visible = (int)bu[2];   // from untrusted network data (uint8, 0..255)

memset(session->gpsdata.skyview, '\0', sizeof(session->gpsdata.skyview));
for (l1=0; l1<session->gpsdata.satellites_visible; l1++) {
    ...
    session->gpsdata.skyview[l1].elevation = (short)(round(elev));
    session->gpsdata.skyview[l1].azimuth   = (short)(round(azi));
    session->gpsdata.skyview[l1].ss        = snr;
    session->gpsdata.skyview[l1].PRN       = (short)bu[...];
    session->gpsdata.skyview[l1].used      = false;
    ...
}
```

`skyview` is defined in `/work/include/gps.h` (line 2938) as:

```c
struct satellite_t skyview[MAXCHANNELS];   // MAXCHANNELS = 184
```

Since `bu[2]` is a `uint8` coming from the CAN bus — an unauthenticated, attacker-controlled source — it can be any value from 0 to 255. When the attacker sends `satellites_visible` in the range **185–255**, the loop writes well past the end of the 184-element `skyview[]` array, causing a **buffer overflow with attacker-controlled data**.

### The fix (after)

The commit adds two security checks before the loop:

1. **Bounds clamp**: `if (MAXCHANNELS <= session->gpsdata.satellites_visible)` — caps the counter to `MAXCHANNELS` to prevent writing past `skyview[]`.
2. **Length validation**: `expected_len = 3 + (12 * satellites_visible)` — checks the incoming buffer length matches expectations and bails out (`return 0`) if it doesn't, preventing out-of-bounds reads from `bu`.

The code comment explicitly says: `// Handle a CVE for overrunning skyview[]` — confirming this is a security vulnerability fix.

### CWE Classification

The primary vulnerability is an **out-of-bounds write** (buffer overflow) — CWE-787. An attacker on the same CAN bus can craft a PGN 129540 message with a large satellite count value, causing the loop to write past the end of `skyview[]`. This can corrupt adjacent memory, leading to denial of service or arbitrary code execution.

An **out-of-bounds read** (CWE-125) from the `bu` buffer is also fixed via the length check, but the write is the more severe exploit vector and the one explicitly called out in the comment. Since both arise from the same root cause and the write is the primary impact, CWE-787 is the most specific and accurate classification. Adding CWE-125 would be redundant padding — one CWE captures the essence of the fix.
