### What was changed

**File 1: `src/modules/annotations.js`** (the core change)

In the "freetext" annotation handler (inside `putPage`), the `anno.color` value (user-supplied via `createAnnotation` options) was previously **directly concatenated** into a PDF content string without any escaping:

```javascript
// BEFORE (vulnerable)
line += " /DS(font: Helvetica,sans-serif 12.0pt; text-align:left; color:#" + color + ")";
```

After the fix, the style string (which includes the color) is properly escaped through `pdfEscape`:

```javascript
// AFTER (fixed)
var defaultStyle = "font: Helvetica,sans-serif 12.0pt; text-align:left; color:#" + color;
line += " /DS(" + escape(encryptor(defaultStyle)) + ")";
```

The `escape` function is `this.internal.pdfEscape`, which escapes `\`, `(`, and `)` characters — the PDF-specific string delimiters.

**File 2: `test/specs/annotations.spec.js`** (new test)

A new test was added that proves the vulnerability existed: it crafts a `color` value containing `000000) /AA <</E <</S /JavaScript /JS (alert("x"))>>>> (` — designed to break out of the `/DS(...)` string and inject a PDF **Additional Action** (`/AA`) that executes arbitrary JavaScript.

### Why this is a security vulnerability

The `/DS` entry in a PDF FreeText annotation is a string delimited by parentheses `(...)`. In the vulnerable code, the `color` value was placed **directly** inside that string with no escaping. An attacker who controls the `color` parameter (which is passed from user input through `createAnnotation`) can:

1. **Close the string** early by inserting `)`.
2. **Inject arbitrary PDF dictionary entries**, such as `/AA` (Additional Actions) with `/S /JavaScript /JS (...)`, which causes the PDF viewer to execute JavaScript when the annotation is activated (e.g., on mouse-over or click).

This is **PDF injection** — injecting raw PDF syntax into a generated PDF document by providing a malicious input value. The injected JavaScript runs in the context of the PDF viewer, potentially leading to local file access, network requests, or other privileged operations depending on the viewer's sandbox.

### CWE Classification

The most specific and accurate CWEs are:

1. **CWE-94: Code Injection** — The attacker injects PDF syntax (including executable JavaScript actions) into the generated PDF, which is essentially code injection into the PDF document format.
2. **CWE-74: Injection** — The broader category covering injection into any interpreted context (here, PDF syntax).

CWE-94 is the most specific, as the injected payload goes beyond mere data injection and adds executable actions (JavaScript code) into the PDF. CWE-74 is also valid as the parent category of injection weaknesses. Both genuinely apply — the color field injects PDF dictionary entries that carry JavaScript code.

The root cause is **missing output escaping** — the `color` value should have been passed through `pdfEscape` (which escapes `(`, `)`, and `\`) before being placed into the PDF content stream, exactly as was done for `anno.contents` on the same FreeText annotation.
