After thorough analysis of all 26 file changes in this single commit:

**Security Vulnerability #1 — SVG Remote Reference Injection (CWE-918):**
The `Sanitizer` trait's `sanitizeSVG()` method was missing a call to `$sanitizer->removeRemoteReferences(true)`. The `enshrined/svg-sanitize` library (version 0.22.0) provides this method to strip external resource references from SVG files before sanitization. SVG is an XML-based format that can embed remote resource references via attributes like `xlink:href`, `<use href="...">`, `<image href="...">`, etc. Without removing these, a malicious uploaded SVG could:
- Cause server-side or client-side requests to attacker-controlled servers (data exfiltration)
- Target internal network services (SSRF)
The fix removes these remote references during the sanitization step. This affects three distinct user-facing upload features (TinyMCE editor, product search images, and product review attachments).

**Security Vulnerability #2 — Missing Authorization on Installer AJAX Routes (CWE-862):**
The `CanInstall` middleware's `handle()` method only checked `! $request->ajax()` before blocking access to `/install` routes after installation. This meant all AJAX installer API endpoints (`/install/api/env-file-setup`, `/install/api/run-migration`, `/install/api/run-seeder`, `/install/api/admin-config-setup`, `/install/api/sample-products-setup`) remained accessible to anyone who knew the route URLs — even after the application was fully installed. An attacker could re-run migrations (wiping data), recreate the admin account, or modify environment configuration. The fix returns a 403 Forbidden JSON response for all AJAX requests to installer routes when the application is already installed.
