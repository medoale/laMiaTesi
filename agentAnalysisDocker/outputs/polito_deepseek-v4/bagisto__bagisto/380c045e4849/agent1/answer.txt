## Analysis

### file_01 — SVG Sanitization (SECURITY FIX)
The change adds `$sanitizer->removeRemoteReferences(true);` before sanitizing an uploaded SVG file. Without this call, the `svgSanitize` library would allow SVG elements like `<image>`, `<use>`, `<a>`, and CSS `url()` references to external URLs. An attacker could craft a malicious SVG that forces the server to make outbound requests to attacker-controlled hosts or internal network resources.

**Vulnerability fixed: Server-Side Request Forgery (CWE-918)**

### file_04 — Admin Creation: `updateOrInsert` → `insert` (SECURITY FIX)
In `adminConfigSetup()`, the code was changed from `DB::table('admins')->updateOrInsert(...)` to `DB::table('admins')->insert(...)`. Before this change, calling the admin config setup endpoint (e.g., via AJAX) after installation would **overwrite** the existing admin user's name, email, and password — effectively allowing an attacker who can reach this endpoint to take over the admin account. With `insert`, the operation will fail with a duplicate-key error if an admin (id=1) already exists, preventing overwrite.

**Vulnerability fixed: Missing Authentication for Critical Function (CWE-306)**

### file_05 — CanInstall Middleware (SECURITY FIX)
The middleware that blocks access to the installer after the app is installed had `if ($this->isAlreadyInstalled() && ! $request->ajax())` — meaning AJAX requests (like those used by the installer's API endpoints for admin creation, seeding, etc.) were **not blocked** at all. The fix properly separates the logic: if already installed, non-AJAX requests get redirected, and AJAX requests get a 403 JSON response. This closes the gap that allowed installer API endpoints to be called after installation.

**Vulnerability fixed: Missing Authentication for Critical Function (CWE-306)** — same CWE as file_04, as both address the same root cause (unauthenticated access to installer functions after installation).

2. **CWE-306 (Missing Authentication for Critical Function)** — The installer's administrative functions (admin creation, database seeding, environment configuration, etc.) were accessible via AJAX even after installation was complete.
