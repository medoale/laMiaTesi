The critical vulnerability is an **Authorization Bypass / Insecure Direct Object Reference (IDOR)**:

In the "participate", "participate_cancel", and "participate_maybe" modes (lines 405-495), the code uses `$getUserUuid` (from the GET parameter) to load a `$user` object, and then performs actions (add/remove/cancel participation) **for that user**. The authorization check at line 424 (`$event->possibleToParticipate() || $participants->isLeader($gCurrentUserId)`) only checks whether the **current user** can participate or is a leader — it does NOT verify that the `user_uuid` parameter belongs to the current user.

So if a regular user (not a leader) can participate in an event, this user can manipulate the `user_uuid` GET parameter to:
- Add any other user to an event (participate)
- Cancel any other user's participation (participate_cancel)
- Set any other user to "maybe" (participate_maybe)

This is an **Authorization Bypass** vulnerability — the user can act on behalf of other users without proper authorization. The fix adds a check: if the current user is NOT a leader of the event, force `$getUserUuid` to the current user's UUID, preventing manipulation of other users' participation.
