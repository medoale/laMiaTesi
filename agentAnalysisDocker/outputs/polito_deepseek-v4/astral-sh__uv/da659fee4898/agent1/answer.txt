## Analysis Summary

This commit adds **ZIP archive member filename validation** to what is clearly the `uv` package manager (a Rust-based Python package manager, analogous to pip). The changes span dependency updates, new error types, a new validation function, integration into two separate ZIP extraction code paths (async streaming and sync seek-based), and an integration test.

### What the before code did

The "before" code already had directory-traversal protection (`enclosed_name()` rejected paths with `..`, root-absolute paths, and null bytes). However, there was **no validation** of ZIP entry filenames for broader character-level issues — control characters like `\n`, `\r`, `\t`, `\0`, `\x01`–`\x1f`, `\x7f`, etc., were all accepted as-is.

### What the after code adds

A new function `validate_archive_member_name()` (file_05) that:

1. **Rejects empty filenames** (`name.is_empty()`)
2. **Rejects filenames containing Unicode control characters** (regex `\p{C}` — which matches Cc, Cf, Cs, Co, Cn categories, including null bytes, newlines, carriage returns, backspace, delete, etc.)

This function is called in **three places**:
- `uv_extract::stream::unzip` (line 90 of file_06): for local file header names
- `uv_extract::stream::unzip` (line 368 of file_06): for central directory entry names
- `uv_extract::sync::unzip` (line 30 of file_07): for seek-based extraction (used for wheel installs)

An `insecure_no_validate()` function provides an emergency escape hatch via `UV_INSECURE_NO_ZIP_VALIDATION` env var.

The integration test `reject_invalid_archive_member_names` (file_08) demonstrates the vulnerability concretely: a malicious wheel `cbwheeldiff2==0.0.1` contains a filename `cbwheeldiff2-0.0.1.dist-info/RECORD` followed by a control character, which is now properly rejected.

### Security impact

Control characters in filenames extracted from ZIP archives can be leveraged by an attacker in multiple ways:
- **Log injection / terminal injection**: A `\n` in a filename could inject fake log entries or terminal escape sequences
- **Null byte truncation** (though already partially mitigated): Could confuse C-based tools or kernel interfaces processing filenames
- **Encoding confusion**: Control characters may cause inconsistent behavior across different ZIP implementations, enabling cross-implementation differential attacks
- **Parsing attacks**: Filenames with embedded separators could break CSV/structured record files (like Python wheel `RECORD` files)

A malicious PyPI package (wheel) could craft a filename with control characters to exploit any of these scenarios during installation.

### CWE Classification

**CWE-20: Improper Input Validation** is the most precise fit. The root cause is that externally-supplied filenames from ZIP archives were accepted without validating their character content. The fix adds explicit input validation with two specific checks (non-empty and no control characters).
