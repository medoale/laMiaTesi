## Analysis

This commit adds **ZIP archive member name validation** to the `uv-extract` crate of the `uv` package manager. The changes span 8 files:

### What changed

1. **`crates/uv-extract/src/lib.rs`** — Added `validate_archive_member_name()` function that rejects:
   - Empty filenames
   - Filenames containing *any* Unicode control characters (regex `\p{C}`), including `\n`, `\r`, `\t`, `\0`, `\x01`–`\x1f`, `\x7f`, etc.
   - Also moved the `insecure_no_validate()` helper here from `stream.rs` so both extraction paths can use it.

2. **`crates/uv-extract/src/stream.rs`** — Added calls to `validate_archive_member_name()` for both local file header entries and central directory entries in the streaming (async) ZIP unpacker.

3. **`crates/uv-extract/src/sync.rs`** — Added a call to `validate_archive_member_name()` in the synchronous ZIP unpacker.

4. **`crates/uv-extract/src/error.rs`** — Added two new error variants: `EmptyFilename` and `UnacceptableFilename { filename }` (with control characters replaced by U+FFFD `�`).

5. **`Cargo.toml`** / **`Cargo.lock`** — Added the `regex` dependency and updated the `async_zip` git revision.

6. **Test file** — Added `reject_invalid_archive_member_names` test using a crafted wheel `cbwheeldiff2==0.0.1` that contains a control character in a filename.

### Security impact

**Before the fix:** The existing code only rejected filenames containing null bytes (`\0`), specifically to prevent directory traversal. All other control characters (escape, newline, carriage return, backspace, tab, etc.) were allowed to pass through unchecked.

**The vulnerability:** A malicious wheel published to PyPI could embed filenames containing control characters. When `uv` processes such a wheel and displays an error message containing the filename (e.g. `Skipping unsafe file name: {path}` or any of the structured error messages in the `Error` enum), those control characters are interpreted by the user's terminal emulator. This enables:

- **Terminal escape sequence injection** — An attacker can use ESC (`\x1b`) sequences to hide real errors, create fake successful output, or manipulate terminal state (a form of UI redressing).
- **Log forging** — Newline/carriage return characters can inject fake log entries, misleading the user about what happened.
- **Backspace injection** — Backspace (`\x08`) can erase parts of output to hide malicious content.

Since `uv` is a package manager that downloads and installs packages from PyPI (an open ecosystem), any attacker can upload a malicious wheel, and a user running `uv pip install <attacker-package>` would be exposed. This is a realistic and exploitable attack vector.

### CWE Classification

The most precise classification is **CWE-150: Improper Neutralization of Escape, Meta, or Control Sequences** — the code failed to neutralize special control characters before they could be interpreted by a downstream component (the terminal emulator).

CWE-117 (Improper Output Neutralization for Logs) could also be argued for the log-forging subset, but CWE-150 is the broader and more precise category since the primary concern is terminal-level control sequence injection (not just log forging), and the fix targets all Unicode control characters broadly.
