## Analysis

This commit changes two files in the **malcontent** project (a malware/content scanner by Chainguard).

### file_02 — The production code change (`archive.go`)

The function `extractNestedArchive()` handles recursive extraction of nested archives during a security scan. The key change is in how it handles extraction failures:

**Before (vulnerable):**
```go
err = extract(ctx, archivePath, fullPath)
if err != nil {
    if c.ExitExtraction {
        return fmt.Errorf("failed to extract archive: %w", err)
    }
    logger.Debugf("ignoring extraction error for %s: %s", f, err.Error())
}

extracted.Store(f, true)

if err := os.Remove(fullPath); err != nil {      // ← unconditionally removes the file
    return fmt.Errorf("failed to remove archive file: %w", err)
}
```

**After (fixed):**
```go
err = extract(ctx, archivePath, fullPath)
if err != nil {
    if c.ExitExtraction {
        return fmt.Errorf("failed to extract archive: %w", err)
    }
    logger.Warnf("extraction failed for %s, retaining archive for scanning: %s", f, err.Error())
}

extracted.Store(f, true)

// only attempt to remove the archive file if we don't encounter an extraction error
// any archives which cannot be extracted will be scanned like non-archive files
if err == nil {                                   // ← only removes on success
    if err := os.Remove(fullPath); err != nil {
        return fmt.Errorf("failed to remove archive file: %w", err)
    }
}
```

**The vulnerability:** When `ExitExtraction=false` (the default), a nested archive that fails extraction was **deleted** — its content was discarded and never scanned. An attacker could craft an outer archive containing a nested archive that is valid enough to be recognized as an archive (e.g., has a `.tar.gz` extension and a valid gzip header) but deliberately broken so extraction fails (e.g., invalid tar structure). The old code would:
1. Try to extract it → failure
2. Log the error at `Debug` level (easily missed)
3. **Delete the file** — the malicious content vanishes
4. Never scan the content of that nested archive

This is a **security scanner evasion** vulnerability: malware hidden inside a broken nested archive escapes detection entirely.

### file_01 — The test change (`action_test.go`)

The test file adds `createBrokenNestedArchive()` (creates a tar.gz containing a valid-gzip-but-invalid-tar nested file) and two tests:
- `TestNestedFailureRetention` — verifies the broken nested archive is **retained** (not deleted) for scanning
- `TestNestedFailureRetentionError` — verifies `ExitExtraction=true` correctly propagates the error

These tests confirm the fix: the scanner should keep unextractable archives so they get scanned as regular file content.

### CWE Classification

The most accurate CWE is **CWE-223: Omission of Security-relevant Information**. The scanner omits from security analysis the content of nested archives that fail extraction — by deleting them before they can be scanned. This directly allows an attacker to evade detection by hiding malicious payloads in deliberately broken archives. The information (the file's raw bytes) is security-relevant and is excluded from processing.

(The vulnerability could also be viewed as CWE-703 / Improper Check or Handling of Exceptional Conditions, but the root security consequence is the omission of data from security analysis — CWE-223 captures the actual harm more precisely.)
