## Key Decisions
- The core change is in `generate_shared_secret_key`: before, it was infallible and silently returned the raw X25519 shared secret; after, it returns `Result` and checks `was_contributory()`. This validates that the peer's public key is not a low-order point (e.g. all zeros) that would produce a zero shared secret.
- This is a cryptographic fix that prevents an attacker from forcing a known (zero) shared secret, which would break confidentiality of all subsequent encrypted communications.

## Critical Context
- Before: `x25519(self.0.to_bytes(), peer_public_key.0.to_bytes())` or `curve25519::scalarmult(...).expect(...)` – both ignored low-order point validation.
- After: `StaticSecret::diffie_hellman(&peer_public_key.0.to_bytes().into()).was_contributory()` – checks contributory behavior per RFC 7748 / libsodium guidance (see https://vnhacker.blogspot.com/2015/09/why-not-validating-curve25519-public.html).
- If `was_contributory()` is false (all-zero result), `CryptoError::SharedSecretKey` is returned and propagated as errors in invite claimer/greeter flows, rather than silently using a zero key.
- The affected flows are mutual authentication / key exchange during user/device invitation (greeter and claimer roles).

## What We Were Analyzing

A single commit in a **Rust cryptographic library** that fixes a vulnerability in X25519 Diffie-Hellman key exchange (`generate_shared_secret_key`).

## The Vulnerability

The function was **missing validation of the peer's public key** during X25519 key agreement. Without this check, a malicious peer could send a **low-order point** (like the all-zeros public key), producing a predictable (all-zeros) shared secret. An attacker who knows the shared secret can decrypt all subsequent encrypted communications.

## What the Fix Does

The commit touches **8 files**:

| File | Change |
|------|--------|
| **file_06** (RustCrypto backend) | Replaced raw `x25519()` with `StaticSecret::diffie_hellman()` + `was_contributory()` check. Returns `Err` if the result is non-contributory (all zeros). |
| **file_07** (libsodium backend) | Changed `.expect("Failed to compute shared key")` (panics) to `.map_err(...)` (returns error properly). |
| **file_05** | Added `CryptoError::SharedSecretKey(String)` variant to the error enum. |
| **file_01**, **file_02** | Invite claimer/greeter code updated to propagate the new `Result`-based error instead of assuming infallibility. |
| **file_04** | `Cargo.toml` added the `"static_secrets"` feature to `x25519-dalek`. |
| **file_03**, **file_08** | Tests updated to handle `Result`, including a new test for the all-zeros public key. |
