## Analysis

The diff reveals a single change in the `doFilter` method of `RequestInputFilter.java` — a Java Servlet Filter for what appears to be NOAA's Live Access Server (LAS).

**The change**: The "Ferret expression" validation check is moved from *before* the `LASUIRequest` object is created and populated, to *after* it is created and populated from the parsed XML.

### The bug in the "before" code

In the original code (lines 365–378 of the `before.txt`):

```java
requestXML = JDOMUtils.decode(requestXML, "UTF-8");
String expression = lasRequest.getProperty("ferret", "expression");  // BUG: lasRequest doesn't exist yet
if (!expression.isEmpty()) {
    // ... reject ferret expressions
}
// ... later:
LASUIRequest lasRequest = new LASUIRequest();  // Created too late!
JDOMUtils.XML2JDOM(requestXML, lasRequest);    // XML parsed too late!
```

The call `lasRequest.getProperty("ferret", "expression")` refers to `lasRequest` *before* the variable is even declared (line 381 in `before.txt`). The check ran against a non-existent object — it could never actually inspect the content parsed from the XML. The intended security gate was structurally broken.

In the corrected code, the sequence is:

1. Decode the XML string
2. Create `LASUIRequest`
3. **Parse** the XML into it via `JDOMUtils.XML2JDOM(requestXML, lasRequest)`
4. **Then** check `lasRequest.getProperty("ferret", "expression")` on the *populated* object

This ensures the validation actually inspects the attacker-supplied content.

### Security impact

Ferret is a data analysis/visualization tool that evaluates mathematical expressions. The code comment says *"Ferret expressions are no longer allowed"* — they were being rejected because they allow execution of arbitrary expressions. In the broken (before) version, an attacker could embed a Ferret expression in the `xml`/`lasxmldoc` query parameter, and the filter would fail to detect and block it. The expression would then be passed downstream for evaluation, resulting in **code injection**.

**CWEs that apply:**

- **CWE-94: Improper Control of Generation of Code ('Code Injection')** — Most specific. Ferret expressions are code/expressions evaluated by the Ferret engine. The filter was intended to reject them but the check was placed too early, allowing them to pass through.
- **CWE-20: Improper Input Validation** — The root cause. The validation was performed at the wrong stage of the pipeline (before input parsing), making it entirely ineffective.
