## Vulnerability: Arbitrary SQL Execution via `previewSql` Endpoint

**CWE-89: Improper Neutralization of Special Elements used in an SQL Command ('SQL Injection')**

### Location

- **Endpoint:** `POST /datasetData/previewSql` (defined in `DatasetDataApi` interface, implemented in `DatasetDataServer`)
- **Implementation:** `DatasetDataManage.previewSql()` (line 434) → `previewSqlWithLog()` (line 401)
- **Execution:** `CalciteProvider.jdbcFetchResultField()` (line 527 of `CalciteProvider.java`) — uses `Statement.executeQuery()` with the raw constructed SQL

### Root Cause

The endpoint accepts a `PreviewSqlDTO` containing:
- `sql` — a Base64-encoded arbitrary SQL string
- `datasourceId` — the target datasource

The SQL is decoded, undergoes only variable substitution and comment removal (no injection prevention), then is embedded into a wrapper:
```sql
SELECT * FROM (<user_sql>) tmp LIMIT 100 OFFSET 0
```

This final SQL is executed via **`Statement.executeQuery()`** (line 527), not a prepared statement. There is **no authorization check** to verify the user has permission to query the specified datasource — `getCoreDatasource()` (line 435) is a simple `selectById()` with zero access control.

### Impact

Any authenticated user can:
1. Read arbitrary data from any datasource in the system, regardless of permissions
2. Use database-specific functions within the SELECT (e.g., `pg_sleep()`, database metadata queries, etc.)
3. Potentially execute data-modifying operations if the database/driver supports multi-statement queries in a subquery context

### Secondary Finding: Numeric Filter Value Injection

In filter processing (`ExtWhere2Str`, `CustomWhere2Str`, `WhereTree2Str`), numeric-type filter values (`deType` 2, 3, 4) are inserted into SQL **without quotes** using `SQLConstants.WHERE_NUMBER_VALUE = "%s"`. While `transKeyword()` escapes `'` → `''` and `\` → `\\`, this provides no protection when no quotes are used. Values like `1 UNION SELECT ...` pass through unchanged and become part of the SQL query.
