## Critical Context
- The `StringM<MAX>` type is a fixed-maximum-length string type. `b.try_into()` leverages Rust's `TryFrom<Vec<u8>>` for the array, which returns `Err(LengthExceedsMax)` if the vector length exceeds `MAX`.
- The old code `Ok(Self(b))` bypassed that check, allowing creation of `StringM` values whose internal data exceeded the declared max, corrupting subsequent operations.
- `file_01` and `file_02` differ only in their XDR source path (`xdr/curr/` vs `xdr/next/`); the fix is identical.
