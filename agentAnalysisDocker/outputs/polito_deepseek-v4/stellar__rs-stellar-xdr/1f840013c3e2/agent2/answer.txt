## Vulnerability Analysis — Final Verdict

### Summary of the Commit

The commit modifies the `StringM<MAX>::from_str` implementation in the `stellar-xdr` crate. Two generated modules (`xdr/curr/` and `xdr/next/`) and one hand-written source file (`lib.rs`) all contain the same core logic change:

**Before (vulnerable):**
```rust
fn from_str(s: &str) -> core::result::Result<Self, Self::Err> {
    let b = escape_bytes::unescape(s.as_bytes()).map_err(|_| Error::Invalid)?;
    Ok(Self(b))
}
```

**After (fixed):**
```rust
fn from_str(s: &str) -> core::result::Result<Self, Self::Err> {
    let b = escape_bytes::unescape(s.as_bytes()).map_err(|_| Error::Invalid)?;
    b.try_into()
}
```

A new test file (`file_03`) is added that verifies boundary behavior: at-limit succeeds, within-limit succeeds, exceeding-limit returns `Error::LengthExceedsMax`, and empty succeeds.

The remaining changes in `file_04` are cosmetic (import reordering, trailing commas, line wrapping, alignment) and are not security-relevant.

### Vulnerability Explanation

The `StringM<MAX>` type is parameterized by a `MAX: u32` const generic, intended to enforce an upper bound on the byte length of the contained string. The `TryFrom<Vec<u8>>` implementation (used via `b.try_into()`) validates that `b.len() <= MAX`, returning `Error::LengthExceedsMax` otherwise.

Before the fix, `from_str` bypassed this validation entirely by calling `Ok(Self(b))`, which wraps the raw `Vec<u8>` directly with no length check. This allows an attacker to construct a `StringM<MAX>` whose internal `Vec<u8>` exceeds `MAX` bytes, violating the type's core invariant. Downstream code that relies on that invariant (e.g., serialization, size calculations, buffer copies) could encounter undefined behavior, out-of-bounds access, or logic errors.

### Classification

This is a **security vulnerability fix** in the category of improper input validation, specifically failing to validate that an input quantity does not exceed a defined maximum.

- **CWE-20: Improper Input Validation** — The `from_str` method did not validate that the unescaped byte length is within the permitted `MAX` bound.
- **CWE-1284: Improper Validation of Specified Quantity in Input** — More precisely, the length of the input (a quantity) was not validated against the maximum allowed value (`MAX`).

Both CWEs apply; CWE-1284 is the more specific match for a length-boundary violation.
