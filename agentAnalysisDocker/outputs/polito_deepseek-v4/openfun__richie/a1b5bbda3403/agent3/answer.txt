Based on my thorough analysis of the entire codebase, I've identified stored cross-site scripting (XSS) vulnerabilities affecting multiple CMS plugins. Here's the detailed evidence:

---

## Confirmed Vulnerability: Stored XSS (CWE-79)

### Root Cause
The `SimpleText` plugin in `simple_text_ckeditor/models.py` correctly sanitizes HTML content via `clean_html()` before saving:

```python
def save(self, *args, **kwargs):
    self.body = clean_html(self.body, full=False)
    super().save(*args, **kwargs)
```

However, **four other CMS plugins** accept user-supplied HTML content from administrators, store it **without any server-side sanitization**, and render it **with the `|safe` template filter** (bypassing Django's auto-escaping).

### Affected Plugins

1. **LargeBanner.content** (`plugins/large_banner`)
   - **Model:** `TextField` — no `clean()` or `save()` sanitization
   - **CKEditor config:** `CKEDITOR_SETTINGS` with `"allowedContent": True` (unrestricted HTML)
   - **Template:** `{{ instance.content|safe }}` in all three templates (`large_banner.html`, `compacted.html`, `hero-intro.html`)
   - Exploit: Any CMS editor can inject `<script>alert(document.cookie)</script>` and it will execute for all visitors.

2. **Section.title** (`plugins/section`)
   - **Model:** `CharField` — no sanitization
   - **CKEditor config:** `CKEDITOR_INLINE_BOLD_CONFIGURATION` with `"allowedContent": ["strong"]` (client-side only — trivially bypassed by sending a raw HTTP POST)
   - **Template:** `{{ instance.title|safe }}` in `section.html` and `section_tiles.html`
   - Exploit: An attacker can bypass the client-side CKEditor restriction by posting a direct request with arbitrary HTML.

3. **LicencePlugin.description** (`courses`)
   - **Model:** `TextField` on `LicencePluginModel` — no sanitization
   - **Template:** `{{ instance.description|safe }}` in `licence_plugin.html`
   - Exploit: Admin can inject arbitrary JavaScript in the description field.

4. **Licence.content** (`courses`)
   - **Model:** Translatable `TextField` on `LicenceTranslation` — no sanitization
   - **Template:** `{{ instance.licence.content|safe }}` in `licence_plugin.html`
   - Exploit: Admin can inject arbitrary JavaScript in the licence content field.

### Why This Is a Vulnerability

- **Django auto-escaping is deliberately disabled** by using `|safe`, meaning Django's built-in HTML escaping is bypassed.
- The `SimpleText` plugin shows the developers knew about the XSS risk and solved it correctly for one model, but did not apply `clean_html()` to the other four models described above.
- The CKEditor client-side `allowedContent` restriction on the Section plugin is trivially bypassable — it provides no server-side security.
