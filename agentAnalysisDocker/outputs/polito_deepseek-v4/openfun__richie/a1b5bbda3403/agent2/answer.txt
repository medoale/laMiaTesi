## Analysis

**The Change (diff):**

The commit replaces the signature comparison in `sync_course_runs_from_request` from:
```python
authorization_header == get_signature(message, secret)
```
to:
```python
hmac.compare_digest(authorization_header, get_signature(message, secret))
```

It also adds the `import hmac` statement at the top.

**Why this is a security vulnerability:**

1. **Timing side-channel:** Python's `==` operator for strings returns `False` immediately upon encountering the first mismatching character. This means the comparison time varies depending on how many characters match — the more characters an attacker guesses correctly, the longer the comparison takes.

2. **Signature recovery:** An attacker can exploit this observable timing difference to iteratively recover the valid signature character by character. Since the signature (`SIG-HMAC-SHA256 <digest>`) authenticates the entire request body using a shared secret, recovering it would allow forging arbitrary authenticated requests to this webhook endpoint.

3. **Impact:** The `sync_course_runs_from_request` endpoint is a webhook that creates and updates course run data in the database. Successful exploitation would allow an attacker to bypass authentication and manipulate course data.

4. **Fix:** `hmac.compare_digest()` is a constant-time comparison function specifically designed to prevent timing attacks. It always takes the same amount of time regardless of how many bytes match.

**CWE Classification:**

The most accurate classification is **CWE-208 (Observable Timing Discrepancy)**, which specifically addresses the use of non-constant-time operations that leak sensitive information through measurable timing differences.
