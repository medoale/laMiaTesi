**Why this is a security vulnerability:**
The original code uses Python's default `==` operator to compare an incoming `Authorization` header against a computed HMAC signature. The `==` operator performs a short-circuiting character-by-character comparison: it returns `False` as soon as the first differing byte is found. This introduces **observable timing differences** — a remote attacker can measure response timing to brute-force the correct HMAC signature one byte at a time, eventually forging a valid signature to bypass authentication on this webhook.

The `hmac.compare_digest()` function performs the comparison in constant time, meaning all bytes are compared regardless of where the first mismatch occurs, preventing the timing side channel.

**CWE classification:**
The primary and most specific weakness is **CWE-208: Information Exposure Through Timing Discrepancy**. This is the textbook case: a cryptographic comparison leaking information through measurable response-time differences.
