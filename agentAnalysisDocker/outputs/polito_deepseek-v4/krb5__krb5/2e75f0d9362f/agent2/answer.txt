## Analysis of the commit

**File:** `src/lib/gssapi/spnego/negoex_util.c` — NegoEx (SPNEGO Extension) parsing code in MIT Kerberos.

The diff makes **two independent security fixes**:

### Fix 1 — Missing NULL pointer check in `parse_nego_message` (lines 255–258 of the diff)

The helper function `vector_base()` can return `NULL` when the `offset` exceeds `msg_len`, or when `count` would cause an out-of-bounds read. In the existing code (before the fix), the return value of `vector_base()` for the extensions vector is stored in `p`, but `p` is immediately dereferenced in the loop:

```c
p = vector_base(offset, count, EXTENSION_LENGTH, msg_base, msg_len);
for (i = 0; i < count; i++) {
    extension_type = load_32_le(p + i * EXTENSION_LENGTH);  // NULL deref!
```

The fix adds the missing `if (p == NULL)` guard before the loop.

**CWE-476 (NULL Pointer Dereference)** — an attacker can craft a malformed NegoEx token with an out-of-range extensions vector offset/count, causing the server or client to crash (denial of service).

### Fix 2 — Missing integer underflow guard in `parse_message` (lines 394–398 of the diff)

In the `parse_message` function, after reading the header fields (`header_len`, `msg_len`), the code computes the remaining header bytes as:

```c
in->len = header_len - (in->ptr - msg_base);
```

The existing bounds check only verifies `msg_len > token_remaining` and `header_len > msg_len` — it does **not** verify that `header_len` is at least as large as the number of bytes already consumed from the input (`in->ptr - msg_base`). If an attacker supplies a `header_len` value smaller than the consumed bytes, the unsigned subtraction wraps around to a huge value, causing `in->len` to become enormous. Subsequent `k5_input_get_*()` calls then read far beyond the bounds of the token buffer.

The fix adds:

```c
header_len < (size_t)(in->ptr - msg_base) || header_len > msg_len
```

**CWE-191 (Integer Underflow / Wraparound)** → **CWE-125 (Out-of-bounds Read)** — an attacker can exploit this to read memory beyond the token buffer, potentially leaking sensitive information or causing a crash.
