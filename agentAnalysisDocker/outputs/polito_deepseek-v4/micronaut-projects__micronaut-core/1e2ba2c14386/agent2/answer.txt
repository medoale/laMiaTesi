The commit fixes a security vulnerability. Here's the full analysis:

**What changed:**

1. **`DefaultHtmlErrorResponseBodyProvider.java`**: Replaced an unbounded `ConcurrentHashMap` cache with a bounded `ConcurrentLinkedHashMap` (max 100 entries). Also added a package-private `getCache()` accessor for testing.

2. **New test file**: `DefaultHtmlErrorResponseBodyProviderCacheMaxSizeTest.java` validates that the cache does not grow without bound, even with many unique error messages.

**Why this is a security vulnerability:**

The `body()` method calls `cache.computeIfAbsent(key, this::html)` where the `key` is an `HtmlErrorPage` record. This record includes:

- `locale` (derived from the HTTP request's `Accept-Language` header)
- `messages` (sanitized error messages from the `ErrorContext`)

The error messages often contain **user-controlled data**. For example:

- `RouteExecutor.createDefaultErrorResponse()` (line 216) constructs: `"Internal Server Error: " + cause.getMessage()` — exception messages commonly include URI paths, query parameters, or other request-specific data.
- `ErrorResponseProcessorExceptionHandler.handle()` (line 49) adds `exception.getMessage()` directly.

Since every unique error message produces a unique cache entry, an attacker can send requests with many different paths, query parameters, or locale headers, each triggering a slightly different error message. Every one creates a new permanent entry in the cache. With an unbounded `ConcurrentHashMap`, this leads to **uncontrolled memory consumption** until the JVM runs out of memory — a classic **denial of service** attack.

The test included in file_02 explicitly demonstrates this: `CustomException` includes `request.getUri()` in its message, so 110 unique URIs produce 110 unique cache entries. The fix caps this at 100.

**CWEs that apply (most specific first):**

- **CWE-770: Allocation of Resources Without Limits or Throttling** — The primary issue. A reusable resource (cache entries) is allocated without any limit on the number that can be created, allowing an attacker to exhaust memory.
- **CWE-400: Uncontrolled Resource Consumption** — The parent category, which also covers the resulting denial of service via memory exhaustion.
