### Vulnerability Found: Path Traversal in `NettyStreamingFileUpload.transferTo(String)`

**File:** `/work/http-server-netty/src/main/java/io/micronaut/http/server/netty/multipart/NettyStreamingFileUpload.java` (lines 109-112)

```java
public Publisher<Boolean> transferTo(String location) {
    String baseDirectory = configuration.getLocation().map(File::getAbsolutePath).orElse(DiskFileUpload.baseDirectory);
    File file = baseDirectory == null ? createTemp(location) : new File(baseDirectory, location);
    return transferTo(file);
}
```

The `transferTo(String location)` method accepts a user-controlled location string and constructs a `File` from it **without any sanitization** of path traversal sequences such as `../`. When a base directory is configured via `MultipartConfiguration`, the call `new File(baseDirectory, location)` does the concatenation — and Java's `File(parent, child)` naturally follows `../` sequences upward, allowing escape from the intended directory.

This is demonstrated in practice in the test suite (`/work/test-suite/src/test/groovy/io/micronaut/upload/UploadController.java`, line 86):
```java
return Flux.from(data.transferTo(title + ".json"))
```
where `title` is a user-supplied form parameter. An attacker providing `title=../../etc/cron.d/malicious` would cause the uploaded file content to be written to an arbitrary filesystem path (e.g., `/etc/cron.d/malicious.json`).

The method is marked `@Deprecated` but remains fully functional.
