The command name changed from the bare `"ioreg"` to the absolute path `"/usr/sbin/ioreg"`. The comment was also updated accordingly.

### Security Assessment

**This is a security fix.** The vulnerability is a **CWE-426: Untrusted Search Path**.

When a process executes a command by name (e.g., `"ioreg"`) without specifying its full absolute path, the operating system searches for the executable in the directories listed in the `PATH` environment variable. If an attacker can manipulate `PATH` (or if the current working directory is included in `PATH` — historically common on some systems), a malicious executable placed earlier in the search order would be executed instead of the legitimate system binary at `/usr/sbin/ioreg`.

This is a classic path interception / "Trojan horse" attack. By hardcoding the full path `/usr/sbin/ioreg`, the fix ensures that only the authentic system utility is invoked, regardless of `PATH` settings.

No other CWE is more specific than CWE-426 here. The fix is not about command injection (no arguments are being injected or unsanitized), and it is not about file path control in general — it is specifically about hardening the executable search path.
