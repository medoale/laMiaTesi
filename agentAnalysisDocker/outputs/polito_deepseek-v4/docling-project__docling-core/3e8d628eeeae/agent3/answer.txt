## Security Audit Summary — docling-core

### Repository Overview
The `docling-core` library provides document parsing, serialization, and CLI tooling. Key modules audited:
- **`docling_core/utils/file.py`** — URL fetching and file resolution
- **`docling_core/cli/view.py`** — CLI entry point that loads user-supplied JSON via URL/path
- **`docling_core/types/doc/document.py`** — Core document model with `load_from_json`, `load_from_yaml`, `save_to_json`, `save_to_yaml`
- **`docling_core/transforms/serializer/`** — HTML and Markdown serializers
- **`docling_core/utils/validate.py`** — File validation via JSON schema

### Confirmed Vulnerability: CWE-918 — Server-Side Request Forgery (SSRF)

**Location**: `docling_core/utils/file.py`, function `resolve_source_to_stream()` (line 107):

```python
res = requests.get(http_url, stream=True, headers=req_headers)
```

**Problem**:
1. **No URL allowlist/blocklist**: The function fetches an HTTP URL supplied directly by the user. The only validation performed is `AnyHttpUrl` (from pydantic), which merely verifies the string is a syntactically valid HTTP/HTTPS URL — it does **not** restrict internal or private IP addresses.
2. **No request timeout**: The `requests.get()` call has no `timeout` parameter, allowing an attacker to make the application hang indefinitely on a slow/non-responsive server (also CWE-400: Uncontrolled Resource Consumption).
3. **Redirects followed by default**: `requests` follows redirects by default, so a seemingly-safe external URL can be used to redirect to an internal endpoint.

**Attack Scenario**: An attacker who can control the `source` argument (e.g., via the `docling view` CLI command) can make the application probe internal services:
- Cloud metadata endpoints: `http://169.254.169.254/latest/meta-data/`
- Internal services: `http://localhost:9200/`, `http://10.0.0.1:8080/`
- Any internal network resource reachable from the host

**Propagation**: The CLI (`cli/view.py` line 56) calls `resolve_source_to_path(source=source)` with the user-supplied command-line argument, directly invoking this vulnerable code path.
