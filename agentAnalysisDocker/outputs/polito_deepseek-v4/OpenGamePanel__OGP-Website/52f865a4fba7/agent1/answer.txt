### What changed

Both `file_01` and `file_02` contain a single, identical category of change: replacing PHP's loose comparison operator (`==`) with the strict comparison operator (`===`) when comparing MD5 password hashes.

**file_01** (login page in `index.php`):
```
- md5($_POST['upassword']) == $userInfo['users_passwd']
+ md5($_POST['upassword']) === $userInfo['users_passwd']
```

**file_02** (API token creation in `ogp_api.php`):
```
- md5($password) == $userInfo['users_passwd']
+ md5($password) === $userInfo['users_passwd']
```

### Security impact: Yes — this is a security vulnerability fix

This is the classic **PHP Type Juggling** vulnerability in password authentication. Here is why it is exploitable:

1. PHP's loose comparison operator `==` performs type coercion. When both operands look like scientific-notation numbers (e.g., `"0e462097431907509062922788533686"`), PHP converts both to floats, and they both become `0.0`. Hence `0 == 0` is `true`.

2. MD5 hashes of certain strings coincidentally start with `0e` followed by only digits (e.g., `md5("240610708")` = `0e462097431907509062922788533686`, `md5("QNKCDZO")` = `0e830400451993494058024219903392`).

3. An attacker who knows that the stored password hash starts with `0e` followed by all digits can authenticate by supplying a *different* password whose MD5 hash also has that property. Loose comparison treats both as the number `0`, so authentication is granted with the wrong password.

4. By changing `==` to `===`, the comparison becomes strict — both value and type must match exactly (string-to-string), so two different `"0e..."` strings will never match unless they are byte-for-byte identical. This eliminates the type-juggling bypass.

### CWE Classification

The root cause is the use of the wrong comparison operator in a security-sensitive context (password verification). The most accurate CWE is:

- **CWE-697** — Incorrect Comparison: the code compares password hashes with loose equality (`==`) instead of strict identity (`===`), enabling type-confusion bypass of authentication.

A secondary, related aspect is that type coercion across incompatible types is the mechanism at play, which could also be described as **CWE-843** (Access of Resource Using Incompatible Type / Type Confusion). However, the most specific and directly applicable identifier for the *root cause* being fixed is **CWE-697** — the comparison itself is the bug.
