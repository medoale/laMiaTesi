## Final Vulnerability Report

After reviewing the full OGP codebase (all modules, includes, and core files), here are the key findings:

### 1. 🚨 **backupdwl.php — Path Traversal / Arbitrary File Read** (Critical)
**File:** `/work/modules/administration/backupdwl.php` (lines 27–28)
```php
$path = getcwd()."/".$_GET['randir']."/";
$fullPath = $path.$_GET['dwfile'];
$fd = fopen ($fullPath, "r");
```
`$_GET['randir']` and `$_GET['dwfile']` are used directly in file path construction with **zero sanitization**. An admin can read any file on the system:
```
?m=administration&p=backupdwl&randir=../../../../etc&dwfile=passwd
```
Then `fopen()` serves and `unlink()` deletes it. This is a **zero-day** — unauthenticated users need admin access, but any admin user (including compromised accounts) can read arbitrary files.

### 2. 🚨 **administration.php — Command Injection via `system()`** (High)
**File:** `/work/modules/administration/administration.php` (lines 112, 119)
```php
$command = "mysqldump ... -u $db_user -p$db_pass $db_name > $backupFile";
@system($command);
$command = "mysql --user=$db_user --password=$db_pass $db_name < ".$_FILES["file"]["tmp_name"];
@system($command);
```
Database credentials from `config.inc.php` are interpolated directly into shell commands. If DB credentials contain shell metacharacters (e.g., password `foo;id`), arbitrary command execution follows. The restore path also uses `$_FILES["file"]["tmp_name"]` — typically safe but the `system()` call with unsanitized credentials is OWASP #1.

### 3. 🚨 **watch_logger.php — Stored/Reflected XSS** (Medium)
**File:** `/work/modules/administration/watch_logger.php` (line 56)
```php
<input name="search" type="text" id="search" value="<?php if(hasValue($search_field)){ echo $search_field; } ?>" />
```
`$_GET['search']` is echoed into the `value` attribute with zero escaping. Payload: `"><script>alert(1)</script>`.

### 4. **test_api.php — Reflected XSS** (Medium)
Already confirmed — POST parameters echoed unsanitized into HTML output.

### 5. **lang.php — Path Traversal via `$_REQUEST['lang']`** (Medium)
`is_dir()` check on user-supplied lang value before file inclusion. If attacker can create a matching directory, arbitrary PHP inclusion follows.

### 6. **database_mysqli.php — No Prepared Statements; Column Names Unescaped** (Medium)
All SQL built via string interpolation after `realEscapeSingle()` — no parameterized queries. Column names (`$key` in `editUser`, `resultInsertId`) are never escaped. Currently safe because keys are hardcoded, but fragile.

### 7. **Multiple Literal `OGP_DB_PREFIX` Bugs** (Low)
`banlist.php`, `addons_manager.php`, `extras.php` use the literal string `OGP_DB_PREFIX` in SQL queries — PHP does NOT interpolate constants in double-quoted strings, so these queries operate on the wrong table names when a prefix is configured.

### Verdict

The **strongest zero-day candidate** is **backupdwl.php path traversal** (#1). It is:
- Simple to exploit (just GET params)
- High impact (arbitrary file read on the server)
- Not previously reported to my knowledge
- In a file unlikely to be audited often (backup download helper)

Second is the **command injection in administration.php** (#2) — perhaps even more impactful (RCE instead of file read), but its exploitability depends on DB creds containing special chars.

**Verdict: Zero-day vulnerability identified in `/work/modules/administration/backupdwl.php` — path traversal allowing arbitrary file read via unsanitized `$_GET['randir']` and `$_GET['dwfile']` parameters.**

### Verdict

**Zero-day vulnerability confirmed: Path Traversal in `/work/modules/administration/backupdwl.php`**

An authenticated admin (or attacker with admin credentials) can read **any file** on the server by sending:
```
GET /index.php?m=administration&p=backupdwl&randir=../../../../etc&dwfile=passwd
```
This bypasses all directory restrictions since `$_GET['randir']` and `$_GET['dwfile']` are used directly in `fopen()` with zero sanitization. The file contents are served with a `Content-Disposition: attachment` header, and the file is then deleted.

**Runner-up zero-day:** Command injection in `administration.php` lines 112/119 — `system()` calls with DB credentials directly interpolated. If the DB password contains characters like `;`, `|`, `` ` ``, or `$()`, arbitrary commands execute. This is especially dangerous in automated deployments where DB passwords may contain special characters.
