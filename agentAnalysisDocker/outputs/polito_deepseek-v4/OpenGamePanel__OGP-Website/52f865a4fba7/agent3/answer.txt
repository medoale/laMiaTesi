## Findings Summary

After thorough exploration of the Open Game Panel web panel codebase, I have confirmed the following vulnerabilities:

### 1. CWE-328: Use of Weak Hash (MD5) for Password Storage
- **File:** `/work/includes/database_mysqli.php`, line 406 (in `addUser()`)
- **File:** `/work/modules/lostpwd/lostpwd.php`, lines 175, 186
- **Details:** All user passwords are hashed with `MD5()` (MySQL's MD5) without any salt. MD5 is cryptographically broken and allows fast offline brute-force attacks. An attacker who gains database access (via SQL injection, backup leak, etc.) can crack passwords efficiently.

### 2. CWE-79: Reflected XSS in Registration Form
- **File:** `/work/modules/register/register.php`, line 54
- **Details:** `$_GET['lang']` is concatenated directly into the HTML form `action` attribute without sanitization. Payload: `?m=register&p=form&lang=x'><script>alert(1)</script><input type='hidden`

### 3. CWE-79: Reflected XSS in Lost Password Form
- **File:** `/work/modules/lostpwd/lostpwd.php`, lines 141-142
- **Details:** `$email_address` from `$_POST` is echoed directly into HTML without escaping when validation fails. The email validation only checks for `@` and `.`, so a payload like `x@y.com<script>alert(1)</script>` passes validation and executes.

### 4. CWE-330: Use of Insufficiently Random Values
- **File:** `/work/modules/lostpwd/lostpwd.php`, lines 25-37 (`makeRandomPassword()`)
- **Details:** Uses `srand((double)microtime()*1000000)` (only ~1M possible seeds) and `rand()` (not cryptographically secure) to generate 8-character passwords. The seed can be brute-forced if the approximate registration/reset time is known.

### 5. CWE-620 + CWE-200: Password Reset Token is the Password Hash
- **File:** `/work/modules/lostpwd/lostpwd.php`, lines 89, 98-99, 178
- **Details:** The reset token (`ch_pass_uid`) sent via email URL is the user's current MD5 password hash (`$user_info['users_passwd']`). This exposes the hash in email transit, URL logs, and referer headers.

### 6. CWE-78 (possible): Command Injection Surface via `clean_server_param_value()` — newline bypass
- **File:** `/work/includes/functions.php`, lines 530-546
- **Details:** `clean_server_param_value()` uses `preg_replace` with `%...%` delimiters (no `m` multiline flag), so **newlines are NOT matched or escaped**. Newlines in bash can terminate a command or introduce new commands. This could allow command injection if user-controlled values containing newlines reach a shell context on the agent side. The chars `* ? ~ # ! { }` are also not escaped.

### Non-issues (investigated but safe):
- `esc_squote()` in `fm_dir.php:367` is correctly applied for single-quoted bash context — safe.
- SQL escaping via `realEscapeSingle()` (`mysqli_real_escape_string`) is used consistently — safe.
- `litefm_check()` path traversal check blocks `/../`, `|`, `;` — safe for normal navigation.
