### Security Impact

This is a **PHP type juggling vulnerability** (also known as a "magic hash" attack). In PHP, the `==` operator performs type coercion. When comparing two strings that both look like numbers in scientific notation — specifically `0eXXXXX...` — PHP evaluates both as the float `0` and the comparison yields `true`, even though the strings are completely different.

Since MD5 hashes are hexadecimal strings, some hash values happen to begin with `0e` followed exclusively by decimal digits (e.g., `0e462097431907509062569788129957`). PHP's `==` would compare these as `0 == 0` → `true`. This means an attacker who provides a password whose MD5 hash is such a "magic hash" can authenticate as any user whose stored MD5 hash is also a "magic hash" — effectively bypassing authentication.

The fix changes `==` to `===`, which compares both value and **type** without coercion, so strings are always compared as strings, eliminating the type juggling attack vector.

### Classification

This is unquestionably a security vulnerability fix — specifically a PHP type juggling vulnerability in password comparison.
