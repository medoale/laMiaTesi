### Vulnerability 1: OS Command Injection via Zip Entry Name — `problem_import_hoj.php`

**File:** `/work/trunk/web/admin/problem_import_hoj.php`  
**Lines:** 159, 175-178

```php
$data_dir = basename($file_name,".json");  // line 159
array_push ($cmds,"mv $tempdir/$data_dir/* $OJ_DATA/$pid/");  // line 160
// ...
foreach($cmds as $cmd){
    system($cmd);  // line 177
}
```

`$file_name` is `zip_entry_name($dir_resource)` (line 148, 122) — the filename from inside an uploaded ZIP archive, unsanitized. `basename($file_name, ".json")` preserves shell metacharacters like `;`, `|`, `` ` ``. If a ZIP entry is named `;id>/tmp/owned;.json`, then `$data_dir = ";id>/tmp/owned;"` and the command becomes:

```
mv /tmp/import_hoj12345/;id>/tmp/owned;/* /home/judge/data/5/
```

This executes the injected `id>/tmp/owned` command. The import script requires `administrator` or `problem_importer` role.

**CWE-78:** Improper Neutralization of Special Elements used in an OS Command ('OS Command Injection')

### Vulnerability 2: Zip Slip / Path Traversal — `problem_import_hoj.php`

**File:** `/work/trunk/web/admin/problem_import_hoj.php`  
**Lines:** 133-134

```php
mkdir($tempdir."/".dirname($file_name));
file_put_contents($tempdir."/".$file_name,$file_content);
```

`$file_name` comes directly from `zip_entry_name($dir_resource)` without sanitization. A ZIP entry named `../../var/www/html/shell.php` resolves `$tempdir . "/../../var/www/html/shell.php"` to `/var/www/html/shell.php`, writing arbitrary file content to the web root. The `mkdir(dirname(...))` succeeds because `/var/www/html` already exists.

**CWE-23:** Relative Path Traversal

### Vulnerability 3: OS Command Injection via File Upload — `phpfm.php`

**File:** `/work/trunk/web/admin/phpfm.php`  
**Line:** 2495

```php
// inside save_upload():
if(file_exists("/usr/bin/dos2unix")&&function_exists("system"))
    system("/usr/bin/dos2unix ".$file);
```

Where `$file = $dir_dest . $filename` and `$filename` = `remove_special_chars($filename)`. The `remove_special_chars()` function (line 2575) only strips `..`, `\`, `/`, `$` — it does **not** filter `;`, `|`, `` ` ``, `&`, `\n`, ` `, `(`, `)`, `{`, `}`, `<`, `>`.

Uploading a file named `;id>/tmp/pwned;.txt` results in the command:

```
/usr/bin/dos2unix /home/judge/data/5/;id>/tmp/pwned;.txt
```

The `id` command executes as the web server user. `$upload_ext_filter` is an empty array (hardcoded in serialized config on line 2), so no extension filtering applies. File upload requires `administrator` or `problem_editor` role.

**CWE-78:** Improper Neutralization of Special Elements used in an OS Command ('OS Command Injection')

**CWE_NAME:** Improper Neutralization of Special Elements used in an OS Command ('OS Command Injection')

The most severe vulnerability is the **OS command injection in `problem_import_hoj.php`** (lines 159, 177): a `system()` call uses `basename(zip_entry_name(...))` without shell metacharacter sanitization, allowing arbitrary command execution via a crafted ZIP archive entry name. Combined with the **Zip Slip path traversal** (lines 133-134) for arbitrary file write and the **unrestricted file upload in `phpfm.php`** (empty `upload_ext_filter`), an authenticated admin/editor can achieve full remote code execution on the server.
