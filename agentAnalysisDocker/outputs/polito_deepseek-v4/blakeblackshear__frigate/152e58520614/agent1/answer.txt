## Analysis Summary

This commit addresses **multiple security vulnerabilities** in an authentication system (the codebase is Frigate, an NVR/security camera application):

### 1. CWE-620 — Unverified Password Change (Primary/Most Critical)
The `update_password` endpoint before the fix allowed **any authenticated user to change any user's password without knowing the current password**. The original code at `update_password` (before.txt line 785-786) simply hashed the new password and wrote it directly:
```python
password_hash = hash_password(body.password, iterations=HASH_ITERATIONS)
User.set_by_id(username, {User.password_hash: password_hash})
```
No check for `old_password` existed. The fix requires the current password to be verified before allowing a change (after.txt lines 833-849), except for admins legitimately managing other users' passwords. The `AppPutPasswordBody` model (file_03) also gains the `old_password` field.

### 2. CWE-613 — Insufficient Session Expiration
Before the fix, **JWT tokens issued before a password change remained valid indefinitely**. The fix:
- Adds a `password_changed_at` timestamp to the User model (file_05) and database migration (file_07).
- Adds an `iat` (issued-at) claim to JWT tokens (file_02, after.txt line 389).
- During token refresh (file_02, after.txt lines 654-670), checks if the token's `iat` is older than the user's `password_changed_at`; if so, the refresh is denied, forcing re-authentication.

### 3. CWE-367 — TOCTOU (Time-of-check Time-of-use) Race Condition
The JWT secret file creation had a race condition. The original code (before.txt line 314):
```python
with open(jwt_secret_file, "w") as f:
```
This truncates/overwrites without atomicity checks — an attacker could exploit a race between the `os.path.isfile()` check and file open, e.g., via a symlink attack. The fix (after.txt lines 314-318) uses `O_WRONLY | O_CREAT | O_EXCL` with `0o600` permissions, ensuring atomic exclusive creation with proper file permissions.

### Additional Security Hardening (supporting changes, not vulnerabilities by themselves)
- Password strength validation (`validate_password_strength`) — enforces minimum length, uppercase, digit, and special characters.
- Session refresh time reduced from 12 hours to 30 minutes (file_01, file_04) — narrows the window for token misuse.
- Logout endpoint accessibility fixed to allow public access (file_02).
- Frontend components updated to collect and send `old_password`, display password requirements, and handle errors in-dialog.
