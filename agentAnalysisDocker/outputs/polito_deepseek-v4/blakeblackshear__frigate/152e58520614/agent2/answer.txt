## Security Vulnerability Analysis

This commit fixes **multiple security vulnerabilities**. Here is my detailed analysis:

### 1. CWE-620: Unverified Password Change (Most Critical)

The `update_password()` endpoint at `/users/{username}/password` previously allowed **any authenticated user** to change **any user's password** without providing or verifying the current/old password:

```python
# BEFORE (vulnerable):
password_hash = hash_password(body.password, iterations=HASH_ITERATIONS)
User.set_by_id(username, {User.password_hash: password_hash})
return JSONResponse(content={"success": True})
```

An attacker who gained access to a valid session (e.g., by session hijacking, XSS, or using an unattended workstation) could trivially change any user's password — including an admin's — locking out the legitimate user and gaining full control.

**After the fix:** The old password is required and verified unless an admin is changing another user's password. The `AppPutPasswordBody` model now includes `old_password: Optional[str] = None`, and the handler verifies it via `verify_password()`.

### 2. CWE-521: Weak Password Requirements

Before the fix, there was **no password strength validation whatsoever** — passwords of any length (including empty strings) were accepted. The fix adds `validate_password_strength()` enforcing:
- Minimum 8 characters
- At least one uppercase letter
- At least one digit
- At least one special character

This prevents users (and attackers) from setting trivially weak passwords.

### 3. CWE-613: Insufficient Session Expiration

Before the fix, when a password was changed, **all existing JWT sessions remained valid** until token expiration (up to 24 hours by default). The fix:
- Adds a `password_changed_at` column to the `User` model (file_05, file_07)
- Adds `iat` (issued-at) claim to JWT tokens (file_02)
- During token refresh, checks if the token was issued before the last password change; if so, rejects the refresh

This ensures that after a password change (especially if done by an admin resetting a compromised account), active sessions from before the change cannot be extended.

### 4. CWE-367: Time-of-check Time-of-use (TOCTOU) Race Condition + CWE-59: Improper Link Resolution Before File Access

The JWT secret file creation was vulnerable:

```python
# BEFORE:
with open(jwt_secret_file, "w") as f:
    f.write(str(jwt_secret))
```

If an attacker could create a symlink at `.jwt_secret` pointing to another file (e.g., `/etc/shadow` or a configuration file), the JWT secret would be written to that arbitrary file. The `"w"` mode would follow the symlink. The fix uses:

```python
# AFTER:
fd = os.open(jwt_secret_file, os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, "w") as f:
    f.write(str(jwt_secret))
```

`O_EXCL` ensures the file is created atomically and fails if it already exists (even as a symlink). The `0o600` permissions restrict access to the owner only, preventing other processes/users from reading the secret.
