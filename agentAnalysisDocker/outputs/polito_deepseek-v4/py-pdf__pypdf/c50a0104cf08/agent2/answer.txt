## Analysis

This commit introduces security hardening for the `PdfWriter` class in the `pypdf` library, specifically in the incremental cloning path of `clone_reader_document_root()`.

### The Vulnerability (Before)

In the **before** code, `clone_reader_document_root()` did this when `self.incremental` was True:

```python
self._objects = [None] * (cast(int, reader.trailer["/Size"]) - 1)
for i in range(len(self._objects)):
    o = reader.get_object(i + 1)
    if o is not None:
        self._objects[i] = o.replicate(self)
```

The `/Size` value in a PDF trailer is **fully attacker-controlled** — it comes directly from the untrusted PDF file. A malicious PDF can set `/Size` to an arbitrarily large value (e.g., 5,000,000 as shown in the new test) while containing only a handful of real objects. The old code would then:

1. **Allocate** a Python list with millions of `None` entries (`[None] * 4,999,999`), consuming huge amounts of memory just for the list pointers (~40 MB for the 5M-element example, and far worse with larger values).
2. **Iterate** through all those millions of slots, calling `reader.get_object()` for each, causing excessive CPU time.

This is a classic **Denial of Service (DoS) via resource exhaustion**.

### The Fix (After)

The commit adds two new keyword-only parameters:
- `incremental_clone_object_count_limit` (default: 500,000) — limits the total number of distinct object IDs
- `incremental_clone_object_id_limit` (default: 1,000,000) — limits the maximum object ID value

A new method `_collect_incremental_clone_object_ids()` first collects actual object IDs from the reader's xref table (only objects that truly exist), then checks both limits before allocating the list. If either limit is exceeded, a `LimitReachedError` is raised.

### CWE Classification

The most specific CWE is **CWE-789: Uncontrolled Memory Allocation** — the product allocates memory in the heap based on an untrusted size value (`reader.trailer["/Size"]`), without ensuring that the size value is within a reasonable limit that controls the amount of allocated memory.

The parent category **CWE-770: Allocation of Resources Without Limits or Throttling** also applies, but CWE-789 is more specific and should be listed first.
