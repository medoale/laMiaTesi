## Analysis

This single commit modifies one function in `/work/crypto/vm/tonops.cpp` — the TVM (TON Virtual Machine) implementation.

**The change:** In `exec_get_in_msg_param`, a null check is added after calling `as_tuple()` on the result of `get_param(st, inmsgparams_idx)`. Before the fix, if the c7 tuple's 18th entry (index 17) is not a tuple (e.g., null, an integer, a cell), `as_tuple()` returns a null `Ref<Tuple>`, and the subsequent call `tuple_index(t, idx)` dereferences that null pointer — causing undefined behavior (crash, potential memory corruption).

**Security impact:** This is a classic null pointer dereference. In a blockchain VM context, a smart contract could craft its c7 register to have a non-tuple value at index 17, then execute `INMSGPARAM` / `INMSG_*` opcodes, triggering the null dereference. This could be used for denial of service (crashing the VM) or potentially more severe exploits depending on how the VM handles the undefined behavior.

**Consistency:** Every other similar pattern in this file (`as_tuple()` / `as_tuple_range()` in `get_unpacked_config_tuple`, `exec_get_prev_blocks_info`, `exec_get_extra_currency_balance`, etc.) already checks for null before proceeding. This function was the only one missing that check.

**Classification:** The fix directly addresses a NULL Pointer Dereference vulnerability.
