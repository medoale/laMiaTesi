### Key Findings

**FINDING 1 (HIGH) — HTTP Chunked Transfer Encoding Integer Overflow**
- **File:** `/work/http/http.cpp:272` + `/work/tdutils/td/utils/misc.h:359-370`
- **CWE:** CWE-190 (Integer Overflow or Wraparound)
- **Impact:** HTTP request smuggling
- **Details:** `hex_to_integer_safe<size_t>()` accumulates the parsed hex value by `integer_value = static_cast<T>(integer_value * 16 + hex_to_int(*begin++))` with no overflow check. On 64-bit platforms where `size_t` is `uint64_t`, sending a hex chunk size with 17+ hex digits (e.g., `"10000000000000000"` = 2^64) wraps to 0. When `size == 0` at http.cpp:273, the chunked parser transitions to `reading_trailer` and terminates the body early. Any remaining bytes on the TCP connection are then interpreted as the start of a new HTTP request, enabling HTTP request smuggling — a classic cross-protocol/pipeline injection attack. The max line size for chunk headers is 16KB, so there is ample room for the overflow payload.

**FINDING 2 (MEDIUM) — ADNL Channel Per-Packet Signature Verification Bypass**
- **Files:** `/work/adnl/adnl-peer.cpp:226` (channel path) vs `:238` (non-channel path), `/work/keys/encryptor.hpp:136-138`
- **CWE:** CWE-347 (Improper Verification of Cryptographic Signature)
- **Details:** Non-channel ADNL packets are Ed25519-signed and verified (`encryptor_->check_signature()` at peer.cpp:238). Channel packets bypass this entirely: `receive_packet_from_channel` (line 213) calls `receive_packet_checked` (line 226) directly without calling `check_signature`. The `EncryptorAES::check_signature()` returns an error unconditionally ("can no sign channel messages"), so per-packet Ed25519 signatures can never be verified for channel packets. The channel relies solely on its AES-CTR+SHA256 encryption construction (encryptor.cpp:119-172) for integrity. While this does provide some level of authentication (requires knowing the channel shared secret), both peers know the shared secret, so a compromised peer can forge channel packets. Furthermore, the AES-CTR+SHA256 construction is non-standard — there is no authenticated encryption mode (no GCM, no HMAC), and the integrity check is a simple SHA-256 of the plaintext prepended to the ciphertext.

**FINDING 3 (LOW) — Debug-Only `td::narrow_cast` in Release Builds**
- **File:** `/work/tdutils/td/utils/misc.h:434`
- **Details:** The `narrow_cast` macro uses `LOG_CHECK` (debug-only assertion) for bounds checking. In release builds, it's equivalent to `static_cast`. This masking is used extensively throughout the codebase (packet sizes, cell counts, TL string lengths, etc.), opening the possibility of undetected integer truncation in production.
