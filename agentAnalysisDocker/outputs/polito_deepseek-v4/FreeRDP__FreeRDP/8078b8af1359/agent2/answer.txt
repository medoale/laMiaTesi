## What We Did So Far

We analyzed a commit across **5 files** in the FreeRDP/WinPR SSPI layer. Each file's diff shows the same security fix being applied in multiple security packages.

### Files analyzed & what each diff shows

| File | Package | Functions Changed | What was fixed |
|---|---|---|---|
| `file_01` | CredSSP | `credssp_FreeCredentialsHandle` | Moved variable declaration, added `sspi_SecureHandleInvalidate(phCredential)` **before** the null check on credentials |
| `file_02` | Kerberos | `krb_FreeCredentialsHandle`, `krb_InitializeSecurityContext` (2 error paths), `krb_DeleteSecurityContext` | Added `sspi_SecureHandleInvalidate()` before null checks (and moved it from after null-check to before, for `FreeCredentialsHandle`) |
| `file_03` | NTLM | `ntlm_FreeCredentialsHandle`, `ntlm_DeleteSecurityContext` | Added `sspi_SecureHandleInvalidate()` before freeing/checking the handle |
| `file_04` | Negotiate | `negotiate_DeleteSecurityContext`, `negotiate_FreeCredentialsHandle` | Added `sspi_SecureHandleInvalidate()` before null checks |
| `file_05` | Schannel | `schannel_FreeCredentialsHandle`, `schannel_DeleteSecurityContext` | Added `sspi_SecureHandleInvalidate()` before null checks |

### The vulnerability pattern (same in all 5 files)

1. **Before the fix**: The code calls `sspi_SecureHandleGetLowerPointer(phCredential)` (or similar) to get the internal pointer, then frees/releases the underlying object, but **never invalidates the handle**. The handle remains valid even though the underlying memory is gone.

2. **After the fix**: `sspi_SecureHandleInvalidate(phCredential)` / `sspi_SecureHandleInvalidate(phContext)` is called **immediately** after retrieving the pointer (and **before** the null check / before freeing). This ensures that even if the pointer is NULL or after the object is freed, the handle cannot be used to re-obtain a dangling pointer later.

### Verdict

This is a **use-after-free** vulnerability: the secure handle remained valid after the backing object was released, so a subsequent `sspi_SecureHandleGetLowerPointer()` call on the same handle would return a pointer to **freed memory**.
