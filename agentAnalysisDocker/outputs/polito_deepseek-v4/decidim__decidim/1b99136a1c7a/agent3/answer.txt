After thorough exploration of this Decidim repository (a participatory democracy Rails framework), I identified three distinct security vulnerabilities that are genuinely present:

## Vulnerability 1: Stored Cross-Site Scripting (XSS) — CWE-79

**Location:** `/work/decidim-meetings/app/presenters/decidim/meetings/meeting_presenter.rb` (lines 16-32)

**Root Cause:** The `MeetingPresenter#title` and `MeetingPresenter#description` methods pass user-controlled content through `HashtagRenderer#render` (which only transforms hashtag patterns), then call `.html_safe` on the result **without any HTML escaping**. The `HashtagRenderer` does not HTML-escape by default (`html_escape: false`). This means `<script>alert(1)</script>` in a meeting title passes through unchanged and is marked safe.

**Exploitation:** The meeting show view (`/work/decidim-meetings/app/views/decidim/meetings/meetings/show.html.erb`, line 19) renders the title directly with no sanitization:
```erb
<h2 class="heading2"><%= present(meeting).title(links: true) %></h2>
```
Any participant who can create/update meetings can inject arbitrary JavaScript that executes in the browsers of all visitors viewing that meeting. Meeting titles and descriptions are created through `Admin::CreateMeeting` (line 31-32), where the `HashtagParser` only transforms `#hashtag` patterns and leaves all other content (including raw HTML) untouched.

## Vulnerability 2: SQL Injection — CWE-89

**Location:** `/work/decidim-core/app/models/decidim/user.rb` (lines 56-59)

**Root Cause:** The `interested_in_scopes` scope directly interpolates array values into a raw SQL `where` clause with **no parameterization or escaping**:
```ruby
scope :interested_in_scopes, lambda { |scope_ids|
  ids = scope_ids.map { |i| "%#{i}%" }.join(",")
  where("extended_data->>'interested_scopes' ~~ ANY('{#{ids}}')")
}
```

**Exploitation:** Called from `/work/decidim-admin/app/queries/decidim/admin/newsletter_recipients.rb` (line 20) with `@form.scope_ids` — an attribute of `SelectiveNewsletterForm` that accepts an `Array` from user-supplied params (line 10: `attribute :scope_ids, Array`). An attacker with admin/newsletter_manager privileges can perform SQL injection via the `scope_ids[]` parameter when sending newsletters.

## Vulnerability 3: Open Redirect — CWE-601

**Location:** Multiple controllers use `params[:redirect_url]` in redirects without host validation:
- `/work/decidim-verifications/app/controllers/decidim/verifications/authorizations_controller.rb` (line 39)
- `/work/decidim-verifications/app/controllers/decidim/verifications/sms/authorizations_controller.rb` (lines 24, 49)
- `/work/decidim-core/app/controllers/decidim/application_controller.rb` (lines 56-57)
- `/work/decidim-core/app/controllers/concerns/decidim/devise_controllers.rb` (line 48)

**Exploitation:** An attacker can craft a URL like `/authorizations/new?redirect_url=http://evil.com/phish` to redirect users (including post-login) to arbitrary external sites, enabling phishing attacks.
