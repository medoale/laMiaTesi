## Critical Context
- The auth path has a noteworthy design characteristic: the `api-key` HTTP header is used for both simple API key auth and as the HMAC secret for JWTs. JWT validation uses `jsonwebtoken` v10.0 with `HS256` algorithm and no algorithm validation override – meaning algorithm-confusion attacks are not possible as the algorithm is hardcoded.
- JWT RBAC is optional (`jwt_rbac: Option<bool>`, default false) and only activated when an `api_key` is set and `jwt_rbac` is true.
- JWT claims include `value_exists` which can scope access to specific collection entries using filters, but the JWT itself is signed with the API key – the token must come from an authorized source.
- Snapshot recovery from URL requires `manage`-level access, meaning only holders of the read-write API key or appropriately scoped JWT can trigger it.
