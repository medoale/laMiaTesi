The three clearest and most impactful confirmed vulnerabilities:

**1. CWE-798: Use of Hard-coded Credentials (settings.py:48)**

The Django `SECRET_KEY` defaults to `'INSECURE_STANDARD_KEY_SET_IN_ENV'` when not set via environment variable. This is a static, publicly-known string from the source code. **2. CWE-22: Improper Limitation of a Pathname to a Restricted Directory (Path Traversal) (urls.py:43-44)**

When `GUNICORN_MEDIA` or `DEBUG` is enabled (both configurable via environment variables), Django's built-in `serve` view is mounted at `r'^media/(?P<path>.*)$'`. The `path` regex group `(.*)` accepts any character sequence including `../` path traversal sequences (e.g., `/media/../settings.py`). While Django's `static.serve` does provide some path sanitization, the unrestricted regex allows requesting files outside the intended `MEDIA_ROOT` directory by using encoded or alternative traversal sequences.

**3. CWE-918: Server-Side Request Forgery (api.py:2454-2471)**

The `RecipeUrlImportView.post` method (route: `api/recipe-from-source/`) accepts user-supplied URLs and makes server-side `requests.get()` calls. The Tandoor share link regex `^(.)*/recipe/[0-9]+/\\?share=...` matches URLs from arbitrary hosts (not just the Tandoor instance's own host). After matching, the URL is transformed by simple string replacement and fetched via `requests.get(tandoor_url)` (line 2460). The `validate_import_url` check at line 2459 attempts to block private IPs, but the DNS resolution is performed at a different time than the actual HTTP request, making it potentially bypassable via DNS rebinding. Furthermore, the `image` URL extracted from the API response is also fetched via `requests.get(recipe_json['image'])` (line 2471) — this URL is attacker-controlled if the initial Tandoor import URL points to an attacker's server that returns a crafted JSON response.
