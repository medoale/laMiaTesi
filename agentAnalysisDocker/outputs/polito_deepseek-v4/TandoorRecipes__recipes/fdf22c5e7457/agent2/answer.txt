## Analysis

This commit fixes a **Server-Side Request Forgery (SSRF)** vulnerability in the Tandoor Recipes application (a Django-based recipe manager). 

### The Vulnerability

The application imports recipes from external URLs and fetches images from user-supplied URLs. The existing `validate_import_url()` function checked the initial URL against private/reserved IP ranges, but had two critical gaps:

**1. SSRF via Unvalidated Redirects (the most severe gap)**

The old code used `requests.get()` and `requests.post()` which, by default, **follow HTTP redirects automatically** (301, 302, 303, 307, 308). The `validate_import_url()` function was only ever called on the **initial/entry URL**, never on redirect targets. An attacker could:

- Host a server at `https://attacker.com/redirect` that redirects to `http://127.0.0.1:6379` (local Redis), `http://169.254.169.254/latest/meta-data/` (AWS metadata), or any internal service
- The initial URL passes validation (it's public, resolves to a public IP)
- `requests.get()` follows the redirect to the internal IP **without any re-validation**
- The server becomes a proxy to internal infrastructure

This is demonstrated in the new test `test_httpbin_mock_redirect()` (file 11, line 143-173) which explicitly tests: initial URL `https://httpbin.org/redirect-to?url=http://127.0.0.1/secret` → redirect to `http://127.0.0.1/secret` → **blocked** by the new code.

**2. SSRF via Encoded IP Addresses**

The old `validate_import_url()` did not detect non-standard IP representations that some systems can resolve:
- **DWORD**: `2130706433` = `127.0.0.1`
- **Hex**: `0x7f000001` = `127.0.0.1`
- **Octal**: `017700000001` = `127.0.0.1`

These formats can bypass URL validators and DNS resolution in unexpected ways across different operating systems and libraries.

### The Fix

The commit introduces `safe_request()` (file_01) which:
1. Sets `allow_redirects=False` on every underlying `requests.request()` call
2. Manually follows redirects one at a time in a loop (max 10)
3. Calls `validate_import_url()` on **every** URL (initial + every redirect hop)
4. Handles relative redirect URLs correctly
5. Detects circular redirects

Additionally, `validate_import_url()` is enhanced to:
- Reject control characters in URLs
- Normalize URLs (encode spaces/special chars for the validator)
- Detect and decode encoded IP addresses (DWORD, hex, octal) and check them against private/reserved ranges

All 26+ instances of direct `requests.get()` / `requests.post()` across the codebase (integration files, providers, views, Telegram bot) are replaced with `safe_request()`.

### Classification

The vulnerability is **Server-Side Request Forgery (SSRF)** — CWE-918. This is the most specific and accurate classification. The redirect-following behavior is specifically a form of SSRF where the attacker uses HTTP redirects as the bypass mechanism, but the underlying weakness class is SSRF.
