## Analysis

This commit makes changes across 13 files in a project called "TandoorRecipes" (a Django-based recipe manager). The changes are tightly focused on fixing **Server-Side Request Forgery (SSRF)** vulnerabilities.

### Before the commit (the vulnerability)

The original `validate_import_url` function (in `file_01/before.txt`) validated URLs by:
1. Running Django's `URLValidator`
2. Resolving the hostname to an IP via `socket.gethostbyname()`
3. Checking if that IP is private/loopback/etc.

However, this had **two critical gaps**:

**Gap 1 — Encoded IP bypass (SSRF):** An attacker could provide an IP address in an alternate encoding that `urlparse` treats as a hostname but that the system still resolves to a local address:
- DWORD format: `http://2130706433/` → `127.0.0.1`
- Hex format: `http://0x7f000001/` → `127.0.0.1`
- Octal format: `http://017700000001/` → `127.0.0.1`

The original code passed the hostname directly to `socket.gethostbyname()`, which on many systems *will* resolve these encodings to the loopback address — but the validator never checked the hostname format itself. The encoded IP would bypass the local-address check because `urlparse` may not recognize it as an IP at all, and the validator only checks the resolved IP after socket resolution, which may be too late in some code paths.

**Gap 2 — Redirect-based SSRF bypass:** The original code only validated the *initial* URL, but all callers used `requests.get()` which follows redirects automatically. An attacker could:
- Use a public URL like `https://httpbin.org/redirect-to?url=http://127.0.0.1/secret`
- The redirect would bypass URL validation entirely, since the redirect target is never re-checked

### After the commit (the fix)

**Fix for Gap 1** (`file_01/after.txt`, lines 74-90): The code now explicitly detects encoded IP formats before DNS resolution:
- Hostnames starting with `0x` are decoded as hex integers and converted to an `ip_address`
- Hostnames starting with `0` (without dots) are decoded as octal integers
- Hostnames that are all digits are decoded as DWORD/integer
- The decoded IP is then checked against all local/special IP ranges

**Fix for Gap 2** (`file_01/after.txt`, lines 105-157): A new `safe_request` function:
- Disables automatic redirect following
- Manually follows each redirect step
- Calls `validate_import_url` on **every** intermediate URL (initial + each redirect target)
- Handles relative redirects by resolving against the original URL
- Detects circular redirects
- Limits to 10 redirects maximum

**Additional hardening:** The validator now rejects URLs with control characters (ord(c) < 32 or == 127), which can be used in SSRF/URL-parser confusion attacks.

**Callers updated** (files 02-09, 12-13): All 11 callers that previously used `requests.get()` or `requests.post()` directly have been switched to use the new `safe_request` wrapper, ensuring the redirect-tracking protection applies everywhere.

**Tests added** (files 10-11): New tests explicitly verify that encoded IP SSRF bypass attempts are blocked and that safe redirect validation works correctly.

### Conclusion

This commit is a **security fix** for a **Server-Side Request Forgery (SSRF)** vulnerability. The two exploitable bypasses (encoded IPs and redirect-based) both fall under the same CWE.
